# 物品池随当前持有实时重建

> 计划文档：供其它智能体执行/对照验收。取代「只增不减」解锁。

## 背景

商店货架与事件商人随机池依赖「池前置」：某商品仅当玩家**当前仍持有**其 `poolPrerequisite` 中全部 `defId` 时才可出现。卖掉最后一件前置物后，依赖它的商品应从池中消失。

## 目标语义

- **池前置是否满足** = 当前是否仍持有对应 `defId`（仓库 + BD 子树；实体另计入模板 `fixedAffixes`）。
- 买到「战士」→「负重训练」可出现；**卖掉最后一件「战士」→ 立刻不再出现**。
- 无 `poolPrerequisite` 的物品始终可进池。

## 实现要点（`GameEngine`）

### `collectOwnedDefIds(): Set<string>`

遍历 `warehouse` + `deploySlots`（`entity` + `children` 递归）：

- `add(item.defId)`
- 若 `type === 'entity'`，再 `add` 其模板 `fixedAffixes`（持有实体即视作拥有这些词条）

### `recomputeItemPool(): void`

```
owned = collectOwnedDefIds()
itemPool = 所有 EntityDef ∪ AffixDef 中
  poolPrerequisite.every(p => owned.has(p)) 的 id
```

- 空前置 → `every` 为 true → 始终进池
- **整表替换**，出售后自然消失
- 删除只增的 `unlockPoolDef` / `syncOwnedToItemPool`

### 调用点

| 时机 | 行为 |
|------|------|
| `generateShopItems` | 开头 `recomputeItemPool()`，过滤用 `itemPool.includes(def.id)` |
| `rebuildItemPool` | 直接 `recomputeItemPool()` |
| `loadSaveData` | 载入持有后 `recomputeItemPool()`（存档旧 `itemPool` 可忽略） |
| `randomItems`（事件商人） | 抽样前 `recomputeItemPool()`，与商店同源 |

### 实时性

购买/出售 → `notify` → 商店重绘 → `generateShopItems` → recompute → 货架即时变。无需在每个 `addToWarehouse` / `sellItem` 上手写增量。

### 性能

持有通常远小于 100，模板数百；仅开商店/出事件货时触发。不做脏标记缓存。

### 存档

`itemPool` 可写入存档作调试快照，**权威来源是持有物**；读档后必 recompute。

## 验收

- [ ] 持有「战士」→ 商店出现「负重训练」（价值上限内）
- [ ] 卖掉全部「战士」→ 负重训练从商店消失（同屏重绘后）
- [ ] 仅 BD 上挂着「战士」、仓库没有 → 仍解锁；卸下且仓库也无 → 消失
- [ ] 实体 `fixedAffixes` 含某前置时，持有该实体即可满足池前置
- [ ] 事件商人随机池与固定商人解锁规则一致
- [ ] 仓库折叠词条名展示保持不变
