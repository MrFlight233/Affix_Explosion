# 启动端-装备体系重构方案

> 基于设计文档 v3（启动端/装备统一实体模型）
> 技术栈：全栈 TypeScript — Vite + Node.js + Express + SQLite

---

## 一、设计目标

将 `kind:'actionable'|'equipment'` 双类型体系重构为**统一的单实体类型** + `启动端` 词条驱动的模式。

核心理念：
- 启动端 = 纯粹的"躯体"（HP、耐力、负重、槽位），不自带攻击能力
- 主动装备 = 独立的"武器"（自带耗时、耗耐、伤害、攻击属性），在时间线上独立触发
- 被动装备 = 属性加成（护甲、回复、HP加成）
- 战斗只攻击对方的启动端，全灭即胜

## 二、统一 EntityDef 接口

```typescript
export interface EntityDef {
  // ---- 共享字段（所有实体都有） ----
  id: string;
  name: string;
  category: string;       // '随从'|'武器'|'防具'|'饰品'|'容器'
  slotCost: number;
  entitySlots: number;
  weight: number;
  value: number;
  fixedAffixes: string[];
  dynamicAffixSlots: number;
  poolPrerequisite: string[];

  // ---- 启动端字段（fixedAffixes 含 'starter' 时有效，否则为 0） ----
  hp: number;
  maxStamina: number;
  staminaRegen: number;   // 每秒
  maxLoad: number;

  // ---- 主动装备字段（isActive=true 时有效） ----
  isActive: boolean;
  staminaCost: number;
  actionTime: number;           // 绝对毫秒（旧 actionTimeMod → 2000 + 旧值）
  damage: number;               // 每次触发伤害（旧 damageBonus）
  attackType: string | null;    // '近战'|'远程'
  attackOrder: string | null;   // '从上往下'|'从下往上'
  priorityTarget: number | null; // 1|2|3|null

  // ---- 被动加成（对父启动端生效） ----
  armorBonus: number;
  regenBonus: number;
  hpBonus: number;
}
```

### 与旧类型的字段对照

| 旧（ActionableEntity） | 旧（EquipmentEntity） | 新 | 迁移说明 |
|------------------------|----------------------|-----|----------|
| `kind: 'actionable'` | `kind: 'equipment'` | (删除) | 不再区分 |
| `category: '角色'/'随从'` | `category` | `category` | '角色' → 全部改为 '随从' |
| `slotCost` | `slotCost` | `slotCost` | 不变 |
| `entitySlots` | `entitySlots` | `entitySlots` | 原 0 的随从 → 改为 1 |
| (无) | `weight` | `weight` | 启动端设为 0 |
| `value` | `value` | `value` | 不变 |
| `fixedAffixes` | `fixedAffixes` | `fixedAffixes` | 'actionable'→'starter' |
| `dynamicAffixSlots` | `dynamicAffixSlots` | `dynamicAffixSlots` | 不变 |
| `poolPrerequisite` | `poolPrerequisite` | `poolPrerequisite` | 不变 |
| `hp` | `hpBonus` | `hp` + `hpBonus` | 启动端用 hp，装备用 hpBonus |
| `maxStamina` | (无) | `maxStamina` | 仅启动端有意义 |
| `staminaRegen` | (无) | `staminaRegen` | 仅启动端有意义 |
| `maxLoad` | (无) | `maxLoad` | 仅启动端有意义 |
| `baseDamage` | `damageBonus` | `damage` | 启动端删除，装备重命名 |
| `baseArmor` | `armorBonus` | `armorBonus` | 启动端删除，装备保留 |
| `baseRegen` | `regenBonus` | `regenBonus` | 启动端删除，装备保留 |

| `attackType` | `attackType` | `attackType` | 从启动端删除，仅装备有 |
| `attackOrder` | `attackOrder` | `attackOrder` | 从启动端删除，仅装备有 |
| `priorityTarget` | `priorityTarget` | `priorityTarget` | 从启动端删除，仅装备有 |
| (无) | `isActive` | `isActive` | 不变 |
| (无) | `staminaCost` | `staminaCost` | 不变 |

## 三、actionTime 转换公式

旧模型：装备 `actionTimeMod` 为修正值（delta），叠加到启动端 `baseActionTime` 上。
新模型：装备 `actionTime` 为绝对毫秒值。

```
主动装备新 actionTime = 2000 + 旧 actionTimeMod
```

| 装备 | 旧 actionTimeMod | 新 actionTime | 说明 |
|------|-----------------|---------------|------|
| 暗影匕首 | -600 | 1400ms | 极速 |
| 细剑 | -500 | 1500ms | 快速 |
| 匕首 | -400 | 1600ms | 较快 |
| 短剑 | -200 | 1800ms | 稍快 |
| 长弓 | 0 | 2000ms | 基准 |
| 木棒 | 0 | 2000ms | 基准 |
| 投石索 | -100 | 1900ms | 稍快 |
| 猎人弓 | -100 | 1900ms | 稍快 |
| 手斧 | +100 | 2100ms | 稍慢 |
| 长矛 | +200 | 2200ms | 稍慢 |
| 链枷 | +300 | 2300ms | 较慢 |
| 冰霜法杖 | +400 | 2400ms | 较慢 |
| 火焰长枪 | +200 | 2200ms | 稍慢 |
| 法杖 | +500 | 2500ms | 慢 |
| 战锤 | +1000 | 3000ms | 极慢 |
| 十字弩 | +800 | 2800ms | 很慢 |
| 双手剑 | +600 | 2600ms | 很慢 |

被动装备（速度之靴等）的 `actionTimeMod` 保留为词条效果，不在实体数据中。

## 四、entitySlots 调整

原随从全部 entitySlots=0（不可装备），现统一改为 1（可装备一件武器）：

| 实体 | 旧 entitySlots | 新 entitySlots |
|------|---------------|---------------|
| 冒险者 | 2 | 2 |
| 战狼 ~ 天使（12个随从） | 0 | 1 |

## 五、词条变更

- `id:'actionable'` → `id:'starter'`，`name:'可行动'` → `name:'启动端'`
- 所有 prerequisite 中的 `'actionable'` → `'starter'`（连击、反击、先攻等）
- `target:'可行动实体'` → `target:'启动端'`

## 六、战斗模型

### 6.1 时间线

每件主动装备独立在时间线上触发（最小堆优先队列）：

```
时间线: 0ms ── 1400ms ── 1800ms ── 2000ms ── 2500ms ── ...
              │         │         │         │
           暗影匕首    短剑      长弓      法杖
           (启动:猎犬)  (启动:冒险者) (启动:弓箭手) (启动:冒险者)
```

### 6.2 目标选择

1. 优先目标位 != null → 检查该位置是否有存活敌启动端
   - 有 → 攻击
   - 无 → 进入步骤 2
2. 按顺序攻击方向搜索最近存活敌启动端
3. 无存活 → 该武器跳过（不影响其他武器）

### 6.3 胜利/失败条件

- 胜利：对方所有启动端 HP ≤ 0
- 失败：我方所有启动端 HP ≤ 0

## 八、注意事项

1. **存档兼容**：ItemInstance 只存 defId，不存完整数据。defId 不变则存档不破。
2. **后端数据**：客户端从不调用 `/api/data/entities`，使用本地 data.ts。后端同步仅为一致性。
3. **被动装备的 damage 字段**：力量护符（被动，damage:3）在引擎中应视为伤害加成加到所有主动武器上。
4. **速度之靴等加速被动**：旧 `actionTimeMod` 转为词条效果，不在实体数据层处理。
