# 启动端-装备体系重构方案

> 基于设计文档 v3（启动端/装备统一实体模型）
> 技术栈：全栈 TypeScript — Vite + Node.js + Express + SQLite
>
> **类型定义源**：当前 `project/shared/types.ts` 未被任何文件引用，所有类型在 `client/src/game/data.ts` 中独立定义。重构选择**维持现状**：新 `EntityDef` 在 `client/src/game/data.ts` 中定义，`shared/types.ts` 同步更新保持一致（仅作参考），服务端 `server/src/routes/data.ts` 同步更新。

---

## 一、设计目标

将 `kind:'actionable'|'equipment'` 双类型体系重构为**统一的单实体类型** + `启动端` 词条驱动的模式。

核心理念：
- 启动端 = 纯粹的"躯体"（HP、耐力、负重、槽位），不自带攻击能力
- 主动装备 = 独立的"武器"（自带耗时、耗耐、伤害、攻击属性），在时间线上独立触发
- 被动装备 = 属性加成（护甲、回复、HP加成）
- 战斗只攻击对方的启动端，全灭即胜

## 二、统一 EntityDef 接口

```typescript
export interface EntityDef {
  // ---- 共享字段（所有实体都有） ----
  id: string;
  name: string;
  category: string;       // '随从'|'武器'|'防具'|'饰品'|'容器'
  slotCost: number;
  entitySlots: number;
  /** 装备: 重量（计入父启动端负重）; 启动端: 0 */
  weight: number;
  value: number;
  fixedAffixes: string[];
  dynamicAffixSlots: number;
  poolPrerequisite: string[];

  // ---- 启动端字段（fixedAffixes 含 'starter' 时有效，否则为 0） ----
  /** 启动端: 基础HP; 装备: 始终为 0 */
  hp: number;
  maxStamina: number;
  staminaRegen: number;   // 每秒
  maxLoad: number;

  // ---- 主动装备字段（isActive=true 时有效） ----
  /** 启动端始终为 false */
  isActive: boolean;
  staminaCost: number;
  /** 主动装备: 绝对毫秒值; 启动端/被动装备: 0（旧 actionTimeMod → 2000 + 旧值） */
  actionTime: number;
  /** 主动装备: 每次触发伤害; 被动装备: 全局伤害加成（加至所有主动武器）; 启动端: 始终为 0 */
  damage: number;
  attackType: string | null;    // '近战'|'远程'
  attackOrder: string | null;   // '从上往下'|'从下往上'
  priorityTarget: number | null; // 1|2|3|null

  // ---- 被动加成（对父启动端生效） ----
  /** 被动加成: 护甲; 启动端: 始终为 0 */
  armorBonus: number;
  /** 被动加成: 回复/秒; 启动端: 始终为 0 */
  staminaBonus: number;
  /** 装备: 分配给父启动端的 HP 加成; 启动端: 始终为 0 */
  hpBonus: number;
}
```

| `poolPrerequisite` | `poolPrerequisite` | `poolPrerequisite` | 不变 |

## 三、actionTime 转换公式

旧模型：装备 `actionTimeMod` 为修正值（delta），叠加到启动端 `baseActionTime` 上。
新模型：装备 `actionTime` 为绝对毫秒值。

```
主动装备新 actionTime = 2000 + 旧 actionTimeMod
```

| 装备 | 旧 actionTimeMod | 新 actionTime | 说明 |
|------|-----------------|---------------|------|
| 暗影匕首 | -600 | 1400ms | 极速 |
| 细剑 | -500 | 1500ms | 快速 |
| 匕首 | -400 | 1600ms | 较快 |
| 短剑 | -200 | 1800ms | 稍快 |
| 长弓 | 0 | 2000ms | 基准 |
| 木棒 | 0 | 2000ms | 基准 |
| 投石索 | -100 | 1900ms | 稍快 |
| 猎人弓 | -100 | 1900ms | 稍快 |
| 手斧 | +100 | 2100ms | 稍慢 |
| 长矛 | +200 | 2200ms | 稍慢 |
| 链枷 | +300 | 2300ms | 较慢 |
| 冰霜法杖 | +400 | 2400ms | 较慢 |
| 火焰长枪 | +200 | 2200ms | 稍慢 |
| 法杖 | +500 | 2500ms | 慢 |
| 战锤 | +1000 | 3000ms | 极慢 |
| 十字弩 | +800 | 2800ms | 很慢 |
| 双手剑 | +600 | 2600ms | 很慢 |

被动装备（速度之靴等）的 `actionTimeMod` 保留为词条效果，不在实体数据中。详见 [6.5 被动加速装备处理](#65-被动加速装备处理)。

### 转换原理

基准值 2000ms = 冒险者（默认启动端）的 `baseActionTime`。

**设计取舍**：旧模型中装备的 `actionTimeMod` 叠加到启动端的 `baseActionTime` 上，因此同一武器装备在不同启动端上速度不同（如匕首在冒险者上为 1600ms，在精灵上为 2100ms）。新模型有意舍弃了这个差异——每件武器的 `actionTime` 是固定绝对毫秒值，不随装备者不同而变化。这样做的原因：
1. 简化引擎逻辑，武器速度独立于启动端
2. 启动端之间的速度差异不再有意义（启动端不自带攻击能力）
3. 后续如需差异化速度，通过词条系统（如敏捷类词条按百分比修正 actionTime）实现

## 六、战斗模型

### 6.1 时间线

每件主动装备独立在时间线上触发（最小堆优先队列）：

```
时间线: 0ms ── 1400ms ── 1800ms ── 2000ms ── 2500ms ── ...
              │         │         │         │
           暗影匕首    短剑      长弓      法杖
           (启动:猎犬)  (启动:冒险者) (启动:弓箭手) (启动:冒险者)
```

### 6.2 目标选择

1. 优先目标位 != null → 检查该位置是否有存活敌启动端
   - 有 → 攻击
   - 无 → 进入步骤 2
2. 按顺序攻击方向搜索最近存活敌启动端
3. 无存活 → 该武器跳过（不影响其他武器）

### 6.3 胜利/失败条件

- 胜利：对方所有启动端 HP ≤ 0
- 失败：我方所有启动端 HP ≤ 0

### 6.4 CombatUnitSnapshot 新结构

战斗开始前，需要从玩家的 `DeploySlot[]` 生成 `CombatUnitSnapshot[]`。新模型下启动端不自带攻击能力，改为列出其装备的主动武器：

```typescript
interface CombatUnitSnapshot {
  // 启动端自身
  entityId: string;
  entityName: string;
  totalHp: number;
  currentHp: number;
  totalArmor: number;       // 基础护甲 + 所有被动装备 armorBonus 之和
  totalStaminaRegen: number;       // 基础耐力恢复 + 所有被动装备 staminaRegenerationBonus 之和
  maxStamina: number;
  currentStamina: number;
  staminaRegen: number;
  currentLoad: number;
  maxLoad: number;
  isOverloaded: boolean;

  // 主动武器列表（每件独立在时间线上触发）
  activeWeapons: {
    name: string;
    actionTime: number;     // 绝对毫秒，固定值
    damage: number;          // 武器自身伤害 + 被动装备 damage 加成
    staminaCost: number;
    attackType: string;      // '近战' | '远程'
    attackOrder: string;     // '从上往下' | '从下往上'
    priorityTarget: number | null; // 1|2|3|null
  }[];
}
```

> **注意**：新结构去掉了旧版的 `totalDamage`（启动端不攻击）和 `dynamicActionTime`（改为每个武器独立管理自己的 actionTime）。

### 6.5 被动加速装备处理

速度之靴（`speed_boots`，旧 actionTimeMod:-500）、时空怀表（`time_watch`，-800）、天使之翼（`angel_wings`，-600）等被动装备在旧模型中通过 `actionTimeMod` 为父启动端加速。

新模型下的处理方式：

1. **数据迁移**：这些被动装备的 `actionTime` 设为 0（它们不是主动装备）
2. **引擎层**：在 `calculateCombatSnapshots()` 中，收集所有被动装备中具有加速效果的词条（如敏捷词条的"耗时-300ms"），聚合后按百分比或绝对值修正每件主动武器的 `actionTime`
3. **设计选择**：具体采用绝对值修正还是百分比修正，取决于后续词条系统的设计细化。当前建议：词条效果直接作用于武器 actionTime（绝对值加减），`actionTime` 最低不低于 500ms

### 6.6 runCombat 时间线引擎流程

当前 `runCombat` 是简化的轮次交替攻击，需完全重写为时间线驱动。以下是核心流程：

```
1. 初始化
   - 从玩家 DeploySlot[] 生成 CombatUnitSnapshot[]（playerUnits）
   - 调用 generateEnemyBD() 生成敌方 CombatUnitSnapshot[]（enemyUnits）
   - 建立 min-heap 优先队列，将所有 activeWeapons 按 actionTime 入队
   - 记录全局时钟 globalTime = 0

2. 主循环（直到一方所有启动端 HP ≤ 0）
   a. 从堆顶取出下一个触发的武器事件 (weapon, ownerUnit, triggerTime)
   b. globalTime = triggerTime（推进时间线）
   c. 耐力恢复：所有单位按 (triggerTime - lastTickTime) * staminaRegen 恢复耐力
   d. 如果 weapon 对应的启动端 HP ≤ 0：跳过（武器随启动端死亡而失效）
   e. 目标选择：
      - 如果 weapon.priorityTarget != null：
        检查敌方第 N 位启动端是否存活 → 是则选中，否则降级
      - 降级：按 weapon.attackOrder 方向搜索最近的存活敌启动端
      - 无存活目标 → 跳过此武器
   f. 耐力检查：
      - 计算总耐力消耗 = weapon.staminaCost * (ownerUnit.isOverloaded ? 1.5 : 1)
      - 如果 ownerUnit.currentStamina >= 总消耗 → 执行攻击，扣减耐力
      - 否则 → 搁置此武器，等待耐力恢复后重新入队（入队时间 = globalTime + 恢复所需时间）
   g. 伤害计算：
      - 物理伤害 = max(weapon.damage - target.totalArmor, 1)
      - 特殊伤害（火焰/毒素由词条提供）无视护甲
      - 应用闪避/反击/荆棘/吸血等词条效果（按 design/05-战斗系统.md 的优先级链）
   h. 重新入队：此武器的下次触发时间 = globalTime + weapon.actionTime，加入堆中

3. 结算
   - 玩家方所有启动端 HP ≤ 0 → 失败
   - 敌方所有启动端 HP ≤ 0 → 胜利
   - 胜利后：growthStacks 累加、金币奖励
```

> **实现要点**：敌方 `generateEnemyBD()` 将原来的简化 `EnemyUnit` 接口改为产出 `CombatUnitSnapshot[]`（敌方启动端 + 随机武器），`EnemyUnit` 接口废弃。

- 存档 → 刷新页面 → 加载存档，状态恢复正确

## 八、注意事项

1. **存档兼容**：ItemInstance 只存 defId，不存完整数据。defId 不变则存档不破。CombatUnitSnapshot 不持久化（仅战斗时内存构建），结构变更不影响存档。
2. **后端数据**：客户端从不调用 `/api/data/entities`，使用本地 data.ts。后端同步仅为一致性。
3. **被动装备的 damage 聚合**：力量护符（被动，damage:3）的 `damage` 在引擎层需作为"全局伤害加成"处理。具体来说，在 `calculateCombatSnapshots()` 中，每个启动端的 `activeWeapons[].damage` = 武器自身 damage + 该启动端所有被动装备 damage 之和 + 词条（如力量词条 damage+2）之和。被动装备自身不参与时间线，它们的 damage 字段的唯一作用就是加成到主动武器上。
4. **速度之靴等加速被动**：旧 `actionTimeMod` 转为词条效果，不在实体数据层处理。详见 [6.5 被动加速装备处理](#65-被动加速装备处理)。
