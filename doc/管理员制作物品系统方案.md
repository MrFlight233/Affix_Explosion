# 管理员制作物品系统

## 概述

管理员制作物品系统允许管理员通过 Web 界面新增、修改、删除游戏中的实体（Entity）和词条（Affix）数据。所有变更实时持久化到服务器 JSON 文件。

## 管理员认证

### 白名单机制

- 服务器 `config.ts` 中维护 `ADMIN_USERS: string[]` 白名单
- 目前仅包含 `admin` 账号
- 管理员中间件双重验证：JWT + 白名单检查

### 添加新管理员

编辑 `project/server/src/config.ts`：
```typescript
ADMIN_USERS: ['admin', 'new_admin_user'],
```

## 数据持久化

### 存储方式

> **v5 架构更新**：数据统一存储在 SQLite（better-sqlite3）中，通过 Drizzle ORM 操作。详见 `doc/实现方案.md`。

- **模板数据**：存储在 `entities` 和 `affixes` 表中，通过 Repository 层操作
- **种子数据**：`project/server/data/game_data.json` 仅作为首次启动/管理员重置时的种子数据源
- **内存缓存**：启动时全量加载到 TemplateCache，运行时读取零 DB 查询
- **管理员修改**：CRUD 操作直接写入 DB + 更新缓存（写穿透），立即生效
- **版本号**：`data_version` 表维护全局版本号，每次模板修改递增

### 数据流

```
管理员操作 → EntityRepo/AffixRepo → DB (INSERT/UPDATE/DELETE) + TemplateCache 更新 → version++
客户端请求 → GET /api/data/all → TemplateCache 内存读取 → JSON 返回（< 1ms）
```

## API 端点

所有 `/api/admin/*` 端点需要 Bearer Token + 管理员权限。

### 管理员检查

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/check` | 检查当前用户是否为管理员 |

### 实体 CRUD

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/entities` | 获取所有实体 |
| GET | `/api/admin/entities/:id` | 获取单个实体 |
| POST | `/api/admin/entities` | 新增实体 |
| PUT | `/api/admin/entities/:id` | 更新实体 |
| DELETE | `/api/admin/entities/:id` | 删除实体 |

### 词条 CRUD

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/affixes` | 获取所有词条 |
| GET | `/api/admin/affixes/:id` | 获取单个词条 |
| POST | `/api/admin/affixes` | 新增词条 |
| PUT | `/api/admin/affixes/:id` | 更新词条 |
| DELETE | `/api/admin/affixes/:id` | 删除词条 |

### 重置

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin/reset` | 重置为默认数据（从 seed JSON） |

## 使用说明

1. 使用 `admin` 账号登录
2. 主菜单出现「制作物品」按钮
3. 点击进入管理页面
4. 左侧标签切换「实体管理」/「词条管理」
5. 搜索框可按 ID/名称/效果过滤
6. 分类筛选按钮快速过滤
7. 点击列表项选中编辑
8. 修改表单内容后点击「保存修改」
9. 点击「+ 新增」创建新物品
10. 点击「重置」恢复默认数据

### 实体表单字段

**基本信息：** ID、名称、占用槽位、重量、价值、固定词条、池前置、默认子实体

**启动端字段：** HP、耐力上限、耐力回复、负重上限

**词条关联：** 固定词条、池前置、词条槽数、预装动态词条（主实体出厂自带动态词条，占用词条槽位）

**可触发动作（原"主动装备字段"）：** 可触发动作（有/无切换，选"无"时隐藏以下字段）、伤害（可为负值=恢复HP）、耐力消耗、触发耗时、针对类型（近战/远程）、针对顺序（从上往下/从下往上）、优先目标（1/2/3/无）、针对目标（友方/敌人/所有）

**被动加成：** 回复加成、生命加成

### 子实体覆写表单字段

每个默认子实体展开后可编辑：

**基本信息覆写：** 名称、槽位占用、实体槽位、词条槽数、重量、价值

**词条配置：** 附加固定词条（与模板合并去重）、池前置、预装动态词条（出厂自带）。显示动态词条已占用/总槽数。

**子实体词条配置（DefaultChildSpec 级别）：** 子实体附加固定词条（与模板 fixedAffixes 合并去重）、子实体预装动态词条（创建实例时自动挂载）

**可触发动作覆写：** 可触发（有/无）、伤害、耗时、耐耗、针对类型、针对顺序、优先目标、针对目标

**被动加成覆写：** 回复、生命

**启动端字段覆写：** HP、耐力上限、耐力回复、负重上限

**嵌套子实体：** 递归展开，子实体的子实体同样可完整编辑

### DefaultChildSpec 数据结构

```typescript
interface DefaultChildSpec {
  defId: string;                        // 引用的实体模板 ID
  overrides?: Partial<EntityDef>;       // 模板字段覆写（替换语义）
  fixedAffixes?: string[];              // 附加固定词条（合并语义，与模板去重合并）
  preloadedDynamicAffixes?: string[];   // 预装动态词条（创建实例时自动挂载）
}
```

### 词条表单字段

ID、名称、分类、效果描述、数值、价值、槽位消耗、可重复、适用目标、前置词条、池前置

## 技术细节

### 服务器端

- `server/src/config.ts`：ADMIN_USERS 白名单
- `server/src/middleware/admin.ts`：管理员中间件
- `server/src/routes/admin.ts`：CRUD 路由
- `server/src/routes/data.ts`：从内存缓存（TemplateCache）读取数据
- `server/src/db/cache.ts`：模板内存缓存 + `server/src/db/repositories/`：Repository 层
- `server/data/game_data.json`：种子数据文件（首次启动 / reset 时导入 DB）

### 客户端

- `client/src/api/client.ts`：admin API 方法 + checkAdmin()
- `client/src/game/data.ts`：reloadData() 支持动态更新数据
- `client/src/ui/admin.ts`：管理员页面 UI
- `client/src/main.ts`：主菜单「制作物品」按钮
- `client/styles/global.css`：管理页面样式

### 数据同步

- 客户端数据从服务端 API 加载，无离线 fallback
- 启动时通过 `loadInitialData()` 获取数据，加载失败显示错误提示
- 管理员修改后通过 `reloadData()` 更新客户端内存中的数据
- 普通玩家始终从服务器获取最新数据
- `reloadData()` 使用数组 mutation (length=0 + push) 保证所有引用自动更新
- **重要**：`showAdminPage()` 初始加载时必须调用 `reloadData()` 同步 `ENTITY_DEFS`/`AFFIX_DEFS`，否则 admin 数据与共享数据脱节
- API GET 请求统一设置 `Cache-Control: no-cache` 防止浏览器缓存过期数据
- 清空可选数组字段（如 `defaultChildren`、`preloadedDynamicAffixes`）时客户端传 `null`，服务端 `entityRepo.update()` 识别 `null` 并转为 `undefined`

## 注意事项

1. 实体分类通过 fixedAffixes 推导（follower/weapon_type/armor_type/accessory_type/container1-4）
2. 新增实体时需要手动添加正确的分类词条
3. 子实体的 fixedAffixes 为**合并语义**（附加到模板 fixedAffixes），而非替换
4. 子实体的 preloadedDynamicAffixes 在 `createItem` 时自动展开为 affix 子项
5. 主实体也可配置 preloadedDynamicAffixes，创建实例时自动挂载
6. 伤害字段可为负值，表示对针对目标恢复 HP
7. 针对目标（targetFaction）：友方=对己方生效、敌人=对敌方生效、所有=对双方生效
8. 删除实体前不会检查是否有其他物品依赖它（v1 简化处理）
9. 重置操作不可撤销
10. 暂时不支持同时编辑同一物品（先写后写覆盖）
