# 被动加成：设置同构主动 + 运行时持续维持

> 日期：2026-08-04  
> 状态：已实现  
> 烤问定稿：Q1–Q26（见计划）  
> 产品用语：目标（不再称「索敌」）

## 心智模型

被动加成 = 无耐力消耗、无触发耗时的主动配置；子树向上聚合到**第一层实体**（不限 starter）；来源存活期间按目标持续维持，死亡硬收。

与命中「持续底盘」分工：存在式长驻 → 被动；有时限状态 → 命中持续。

产品用语仍为「被动加成」；光环仅为多目标形态俗称。

## 数据

```ts
passiveEffects: { displayName, stat, op, params: { amount } }[]
// stat ∈ maxHp | maxStamina | maxLoad | hpRegen | staminaRegen
passiveTargetCondition / passiveTargetCount
hasPassiveBonuses
```

旧五列迁入后保存写 0。v1 无 percent。

## 运行时

每 tick：清已死来源 → 全量重算被动 → 回复 → 开火。  
`有效 = 基础 + passiveMods + durationChassis`。  
不受 `targeting_modifier`。不序列化 mods。

## 实现落点

- `project/shared/passiveBonusUtil.ts`
- `engine.ts` 采集 / `battle/passives.ts` 重算
- Admin 主动/被动分区标题（上下堆叠，非左右栏）；BD 静态预览；战斗修饰汇总
- DB migrate + seed（含 `inspirational_aura` 鼓舞样板）
- **注意**：开战快照只存基础属性，禁止把被动结果写回 snapshot（否则会叠算）

## UI 展示同步（卡面 / 悬浮窗）

根因曾出现「真实耐回 13、卡面仍 8」：

1. 开战须在挂 `combat*Units` **之前** `recomputePassiveBonuses`（勿等 Simulator 构造）
2. 卡面 / `battlePatch` 须刷 `cu-sregen` / `cu-hregen` / `cu-load` / `cu-pmods`
3. 悬浮窗 `showSimTooltip` / `bindSbTooltips` 须传入 `getCombatUnit`（战斗取 runtime；BD 取 `previewBdRuntimes`）
4. 有 runtime 时负重用被动后 `maxLoad`，勿仅退回 `computeStarterLoad`（后者只计「仅自己」）

## 规范

- 动态过滤慎挂上限类
- 非「仅自己」卡面注明：由所在第一层实体维持，其阵亡后失效
- 玩家可见文案用「目标」，不用「索敌」

## 手测清单

1. Admin：实体主动目标 / 被动目标上下分区；保存后五列为 0、effects 有值
2. BD：挂「仅自己」生命加成 → 面板 HP 上升；挂友方鼓舞 → 多槽耐力恢复上升
3. 木桩第一层挂被动 → 光环仍生效；木桩无主动触发
4. 战斗：来源阵亡 → 受益修饰立即消失；HP 上限下降时 current 钳制
5. 敌方减益被动 → 敌方面板下降；不受 targeting_modifier 词条影响
6. Tooltip / 卡面：标签为「目标」；非仅自己显示根维持文案；战斗中显示「战斗修饰」汇总
7. `npm run seed:publish` 后种子含 `inspirational_aura`
8. 挂友方鼓舞后：BD 卡面与悬浮窗耐回均为基础+5；开战首帧与 patch 同值；战后不叠成基础+10
