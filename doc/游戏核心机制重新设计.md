# 游戏核心机制重新设计

## 概述

本次是对游戏核心机制的全面重新设计。取消收集阶段、移除硬编码的实体分类、重构战斗系统、移除护甲和活力值系统。

---

## 一、阶段系统

### 阶段循环

回合自然数递增。奇数回合 = 探险阶段，偶数回合 = 战斗阶段。

| round | phase | 说明 |
|-------|-------|------|
| 1 | 探险 | 开局回合 |
| 2 | 战斗 | 第一场战斗 |
| 3 | 探险 | 第二次探险 |
| 4 | 战斗 | 第二场战斗 |
| 5 | 探险 | 第三次探险 |
| ... | ... | 持续递增，无上限 |

### 阶段流转

```
探险(phase=1) → 战斗(phase=2) → 探险(phase=1) → 战斗(phase=2) → ...
```

- 战斗获胜或失败都进入下一个探险阶段
- 战斗获胜只给金币，不掉落物品
- 取消"层"概念，只保留 round

### GamePhase

```typescript
export type GamePhase = 1 | 2; // 1=探险 2=战斗
```

### 金币

- 初始：40 金
- 每次探险阶段：(round + 1) / 2 × 10 金
- 战斗获胜：额外金币

## 二、实体模型

### 原则

**实体就是实体。** "武器"、"防具"、"饰品"、"容器"仅仅是描述性词条。没有硬编码的"启动端"、"装备"、"主动装备"、"被动装备"分类。

所有实体都有完整的战斗属性（hp、maxStamina、staminaRegen、maxLoad），放在第一层或子孙槽位的区别只在于实际使用场景。

### starter 词条

- 拥有 `starter` 的实体 = 第一层战斗单位
- 自身 `isActive=true` 时会触发动作
- 子孙中 `isActive=true` 的实体也会触发
- **不能放入其他实体的实体槽中**

### 无 starter 的实体

- 放在第一层 → 木桩（有 HP 可被攻击，无动作触发）
- 放入其他实体槽位 → 占用槽位，有 `isActive` 时由父实体触发

### isActive（可触发动作）

- 只是一个布尔属性
- 没有"武器"概念——武器只是 `weapon_type` 词条的标签
- 每个可触发实体独立计时、独立触发、互不阻塞

### 属性显示

- **HP**：始终显示
- **耐力上限、耐力回复、负重上限**：仅在拥有 `starter` 词条时显示

## 三、第一层槽位系统

替换原有的活力值(vitality)系统。

### 规则

- 第一层槽位数量 = 当前 round
- 所有第一层实体占用其 `slotCost` 数量的第一层槽位
- 第一层总占用 ≤ 第一层槽位数量

### 已删除

- `vitality1`、`vitality2`、`vitality3` 词条
- `GameState.vitality`、`GameState.maxVitality`
- `getVitalityUsed()` 函数

---

## 四、战斗系统

### 参战规则

- **所有第一层实体**都参与战斗
- 有 `starter` → 自身 + 子孙 `isActive=true` 实体独立在时间线上触发
- 无 `starter` → 木桩（有 HP，可被攻击，无动作）

### 伤害（无护甲）

```
dmg = weaponDamage
```

- 正 = 伤害，负 = 恢复 HP，零 = 无效果
- 没有最小 1 伤害的限制
- `targetFaction` 决定目标筛选：友方 / 敌人 / 所有

### 已删除的护甲相关

- `EntityDef.armorBonus`
- `CombatUnitSnapshot.totalArmor`
- 伤害计算中的护甲减伤逻辑

### 死亡与复活

- HP ≤ 0 → 死亡：子孙实体退出战斗，动作停止触发
- HP 恢复到 > 0 → 复活：重新加入战斗
- 一方所有第一层实体 HP ≤ 0 → 战败

### 耐力与超重

- 负重 > 负重上限 → 该实体子孙所有可触发动作的 `staminaCost × 1.5`
- 搁置期间并行等待：谁的耐力先满足谁先触发
- 触发后才开始下一次耗时倒计时

|------|------|
| 商人价值上限 | `round × 10` |

| 探险阶段金币 | `(round + 1) / 2 × 10` |
