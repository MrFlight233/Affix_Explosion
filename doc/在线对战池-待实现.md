# 在线对战池 — 完整实现方案

> 状态：已实现
> 最后更新：2026-07-22

---

## 一、概述

在线对战池是玩家间**异步匹配对战**系统。核心流程极简：

1. 进入战斗阶段时，玩家 BD **自动上传**到对战池
2. 同时从池中**随机抽取**同回合的其他玩家 BD 作为对手
3. 池中无对手时，**自动获胜**

**设计原则**：不计算战力、不统计战绩、不分楼层。对战池只是一个 BD 交换市场——上传自己的，抽别人的。

## 三、BD 数据格式

### 3.1 存储格式

对战池中的 `bd_json` 是 `DeploySlot[]` 的 JSON 序列化：

```ts
interface DeploySlot {
  entity: ItemInstance;        // 第一层实体
  children: ItemInstance[];    // 启动端直属子项（装备/词条）
}

interface ItemInstance {
  instanceId: string;          // 唯一运行时 ID
  defId: string;               // 模板定义 ID
  type: 'entity' | 'affix';
  children?: ItemInstance[];   // 嵌套子项
  overrides?: Partial<EntityDef>; // 实例级字段覆写
}
```

### 3.2 服务端校验

`battleRepo.validateBdDefIds()` 递归检查 BD JSON 树中所有 `defId` 是否在 `templateCache` 中存在。覆盖 entity 和 affix 两种类型。当前校验已足够防篡改。

### 3.3 跨版本兼容

服务端校验依赖当前模板数据。如果模板变更（删除/重命名 defId），旧 BD 上传会失败。建议对战池匹配时增加 `data_version` 过滤。

### 任务 1：简化数据库 + 仓储（先做，后续任务依赖此改动）

**涉及文件**：

- `project/server/src/db/repositories/battleRepo.ts` — 以下三项改动

#### 1a. 简化 `upload()`

```ts
upload(userId: number, username: string, round: number, bdJson: string): number {
  // defId 校验保留（不变）
  // 纯 INSERT，允许多条
  const db = getDB();
  const result = db.prepare(`
    INSERT INTO battle_pool (user_id, username, round, bd_json)
    VALUES (?, ?, ?, ?)
  `).run(userId, username, round, bdJson);
  return Number(result.lastInsertRowid);
}
```

#### 1b. `findByFloorRound()` → `findByRound()`

改为直接返回随机 1 条（不再返回列表让客户端挑）：

```ts
findByRound(round: number): any | null {
  const db = getDB();
  const row = db.prepare(`
    SELECT id, username, round, bd_json
    FROM battle_pool
    WHERE round = ?
    ORDER BY RANDOM()
    LIMIT 1
  `).get(round) as any;
  if (!row) return null;
  return { ...row, bd_json: JSON.parse(row.bd_json) };
}
```

#### 1c. 删除 `updateStats()`

整个方法删除。`battle_pool` 不再追踪战绩。

### 任务 3：游戏流程接入对战池

**文件**：`project/client/src/game/engine.ts`

**修改 `runCombat()` 方法**：

```
改造后流程:
1. buildRuntime(player) → 玩家 CombatUnitSnapshot[]
2. 上传 BD: await uploadBD(round, deploySlots)
     └─ 上传失败静默忽略，不影响战斗
3. 拉取对手: const { opponent } = await getBattlePool(round)
4. 判断:
     - 有对手 → parse bd_json → buildRuntime → 正常战斗
     - 无对手/请求失败 → 自动获胜（直接结算，跳过战斗引擎）
5. runBattle(玩家, 对手)  // 仅在有对手时执行
6. 结算金币 + growth（不变）
```

**对手选择**：服务端 `ORDER BY RANDOM() LIMIT 1` 直接随机取 1 个，客户端不再做二次选择。

**池空自动获胜**：无对手时直接视为胜利，正常发放金币和 growth 奖励，不调用 `_runBattleCore()`。

## 五、数据流

```
探险阶段 (phase=1)
  │  玩家编辑 DeploySlot[]
  │
  ▼
进入战斗阶段 (phase=2)
  │
  ├─ 1. 上传 BD: POST /api/data/battle-pool { round, bd_json }
  │     └─ battleRepo.upload() → DELETE 旧记录 → INSERT 新记录
  │
  ├─ 2. 拉取对手: GET /api/data/battle-pool?round=2
  │     └─ battleRepo.findByRound() → ORDER BY RANDOM() LIMIT 1 → 返回 { opponent }
  │
  ├─ 3. 判断:
  │     ├─ 有对手 → parse bd_json → 正常战斗
  │     └─ 无对手 → 自动获胜，跳过战斗引擎
  │
  └─ 4. 结算（不变）
```

## 六、关键决策

| # | 决策项 | 决定 | 理由 |
|---|--------|------|------|
| 1 | 战力分 | 删除 | 无法准确计算，不做就是最好的 |
| 2 | 战绩统计 | 删除 | 简化系统，对战池只做 BD 交换 |
| 3 | 楼层（floor） | 删除 | 当前游戏无楼层概念，只用 round 匹配 |
| 4 | 上传时机 | 进入战斗阶段时自动上传 | 无需玩家操作，静默完成 |
| 5 | 对手选择 | 服务端 `ORDER BY RANDOM() LIMIT 1` | 一次返回 1 个，客户端不挑 |
| 6 | 池空处理 | 自动获胜 | 无对手 = 不必战斗，直接胜利 |
| 7 | 重复上传 | 允许多条（纯 INSERT） | 同一用户同回合可上传多次，抽取时按概率自然分布 |
| 8 | 版本校验 | 增加 `data_version` 过滤 | 后续迭代 |
