# Bug 修复：Admin 命中效果保存后丢失

> 日期：2026-08-04  
> 状态：已实现

## 问题描述

制作物品中：新建/编辑实体，将「可触发动作」设为有并添加效果，保存成功后效果为空。

复现证据：库中 `inspirational_aura`（鼓舞光环）`is_active=1` 且 `on_hit_effects='[]'`，`updated_at=2026-08-04T06:48:02Z`。

## 根因分析

1. Admin 效果编辑器的「数据」下拉同时列出即时白名单与持续底盘白名单。
2. 默认类型为「即时」。若用户把数据改成生命恢复 / HP 上限等底盘属性（光环类常见配置），或选「持续」却未填 `durationMs`，客户端仍把该条提交上去。
3. 服务端 `normalizeOnHitEffects`（`entityDefToRow`）按白名单校验，**不合法条目直接丢弃且无错误**，于是落库为 `[]`。
4. 保存接口仍返回 200，界面提示成功，重新打开表单看不到效果。

## 修复方案

| 路径 | 改动 |
|------|------|
| `project/client/src/ui/adminHitEffects.ts` | 先选「影响数据」再定类型/Tick（见跟进文档）；保存前 `collectOnHitEffectsFromDom` normalize，非法则阻止保存 |
| `project/client/src/ui/admin.ts` | 实体/词条保存使用 `collectOnHitEffectsFromDom`；有丢弃则 toast 阻止保存；构建对象纳入 try/catch |

> 跟进：交互改为「先选影响数据 → 再定类型 / Tick 显隐」，见 `doc/2026-08-04-Admin命中效果先选数据.md`。

## 明确不做

- 不改服务端静默 normalize 语义（读档仍需容错）
- 不在本单实现光环引擎
