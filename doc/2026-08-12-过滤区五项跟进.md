# Admin 过滤区与条件 UI 五项跟进

> 日期：2026-08-12  
> 状态：已实现  
> 用户确认：预留条件从 Admin 移除；去掉过滤 `filterBy: null` /「清除过滤」

## 修改点 1：移除词条过滤「清除过滤」与 `null` 写入

### 现状

词条主动目标覆写有「清除过滤」→ 写 `targetingModifier.filterBy: null`。种子无此用法，配置强制空池无必要。

### 期望

删除勾选；勾选过滤项则覆写数组，全不勾则不写 `filterBy`（继承）。design 不再写 filterBy 的 null=清除。

### 原因

词条改目标应给出具体条件，不必单字段 null。

### 实现

- `project/client/src/ui/admin.ts`：去掉 `af-tm-filter-clear` 渲染与保存
- `design/04-词条介绍.md`：更新 `TargetingModifier.filterBy` 注释
- `itemPool.ts`：null 展示保留兼容文案即可

## 修改点 2：Admin 移除未生效的「有负面 / 有增益」

### 现状

`EXTRA_FILTER_OPTIONS` 含 `has_debuff` / `most_buffs`，战斗未维护对应状态，配置无效。

### 期望

Admin 不再提供；引擎 case 与 `FILTER_LABELS` 保留兼容。

### 原因

可配却无效会误导配置。

### 实现

- `targetingUtil.ts`：从 `EXTRA_FILTER_OPTIONS` 删除两项
- `design/04`、`design/05`：注明 Admin 不暴露、仍为预留

## 修改点 3：过滤行标题样式对齐

### 现状

`.adm-filter-row-title` 为主色 600，外层 label 为次要灰 500。

### 期望

行标题改为 `var(--adm-text-secondary)` + `font-weight: 500`。

### 原因

内层标题不应比字段名更抢眼。

### 实现

- `global.css` 中 `.adm-filter-row-title`

## 修改点 4：阵营目标说明 hint

### 现状

友方/敌人/根实体为阵营 OR；仅根实体=发动者；全不选=空目标。hint 未写清。

### 期望

三处过滤区 hint：`目标可多选（OR）；仅「根实体」=发动者；全不选=空目标`；词条覆写另加「勾选覆写 / 不勾不修改」。  
条件行上方固定 hint：`条件可多选（AND）；需同时满足`。  
拥有词条行上方固定 hint：`拥有词条可多选（OR）；拥有其中任一即匹配`。

### 原因

机制正确，缺配置说明。

### 实现

- 实体/被动/词条调用处更新 `hint`

## 修改点 5：触发条件「需求词条」同行

### 现状

需求词条 popover 标题在上、控件在下。

### 期望

与拥有词条相同：`adm-filter-row` + 空 label popover。

### 原因

布局统一。

### 实现

- `adminPassiveBonuses.ts` / `adminHitEffects.ts`

## 验收

1. [x] 无「清除过滤」；有选项写数组，全不勾省略 filterBy
2. [x] 条件行无有负面/有增益（已从 EXTRA_FILTER_OPTIONS 移除）
3. [x] 行标题次要灰、字重 500
4. [x] hint：`目标可多选（OR）；仅「根实体」=发动者；全不选=空目标`；词条侧含不勾=不修改
5. [x] 需求词条与 chips 同行（被动 + 命中）
6. [x] 其它 popover 仍用默认上下布局（未改全局 popover API）

## 明确不做

- 不实现 debuff/buff 管线；不删引擎 case
- 不把未勾过滤写成 `[]`；不改排序/数量「无（清除）」
