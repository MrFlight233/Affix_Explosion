# 结算回顾与首战入历史

## 规则

- **结算页**：仅通关（打完 maxRound 战斗并点继续）出现。
- **版式（结算 + 历史单局详情共用）**：三分区——上总统计（单行横排；结算页「返回主菜单」在顶栏左侧 / `leadingHtml`）、左下回合列表、右下选中回合详情（双方 BD + 日志）。点左侧场次切换右侧；默认选中第一场；无场次时右侧空态。BD 卡片默认可折叠/展开。
- **可拖分界**：列表|详情竖线、BD|日志横线（`localStorage: fg-run-review-split`）。
- **历史回顾**：本局打过 ≥1 场战斗即可出现（`status: in_progress`）；每场结束 upsert 同一条；通关标 `cleared`。
- 列表行：时间、胜/负、状态徽章；不显示序号/金币/已打场数/回合上限。
- 单局详情标题为**归档时间**（`created_at`），不是「爬塔回顾」。
- 存档字段：`historyRunId`；首战 POST 建档，之后 PUT 更新。

## 实现要点

- 服务端：`PUT /api/history/:id`；列表摘要含 `status` / `wins` / `losses`
- 客户端：结束态 `syncHistoryRun`；`ui/runReview.ts` 的 `renderRunReviewShellHtml` + `bindRunReview`（`data-select-battle`）共用结算与历史详情
- 分界：`splitters.bindRunReviewSplitters`（`#fg-run-v-split` / `#fg-run-h-split`）
- 换场后绑定 `bindSbTooltips` + `bindReviewCardCollapse`
- CSS：`.fg-run-layout` / `.fg-run-header-compact` / `--fg-run-list-pct` / `--fg-run-log-pct`
- 文档：`design/01`、`08-正式局设计系统`、`02` 已同步
