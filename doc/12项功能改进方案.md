# 12 项功能改进方案

> 状态：计划阶段，待执行
> 创建日期：2026-07-17

## 背景

用户提出了 12 项功能改进需求，覆盖数据模型、商人系统、战斗 UI、实体嵌套、拖拽排序、登录流程等多个方面。

## 需求清单

| # | 需求 | 说明 |
|---|------|------|
| 1 | 冒险者不入仓库 | 开局时自动部署冒险者到出场面板，不放入仓库 |
| 2 | 商人系统改进 | 不限数量、仅价值限制、类型筛选、事件商人一次性 |
| 3 | 战斗面板切换 | 战斗时出场面板→玩家战斗状态面板，敌人面板→敌人战斗状态面板 |
| 4 | 战斗实时数据 | 实时显示每个实体的血量、耐力、护甲 |
| 5 | 武器倒计时 | 主动武器的剩余触发时间以倒计时显示 |
| 6 | 战后保留面板 | 战斗结束后保留双方战斗状态面板+战斗日志 |
| 7 | 商人拖拽购买 | 从商人面板拖拽到出场/仓库面板即购买 |
| 8 | 容器实体嵌套 | 容器词条提供实体槽位，支持多层嵌套组 BD |
| 9 | 词条展开/收起 | 实体行如果有词条，显示第二行用于展开/收起词条 |
| 10 | 拖拽排序 | 实体与实体之间、词条与词条之间可通过拖拽排序 |
| 11 | 默认登录页 | 未登录时默认进入登录页面 |
| 12 | 返回主菜单 | 存档按钮左侧添加"返回主菜单"按钮 |

---

## 架构决策

1. **DeploySlot 混合嵌套模型**：保留 `DeploySlot.children`（启动端直属子项），容器实体的 `ItemInstance.children` 处理深层嵌套。后续可考虑统一。

2. **实体槽位动态计算**：`effectiveSlots = def.entitySlots + 容器词条等级（container1→+1, container2→+2, container3→+3, container4→+4）`，高级覆低级，不叠加。

3. **战斗时间线**：数组扫描 O(n) 代替最小堆（武器总数 < 15，性能足够）。

4. **战斗 UI 刷新**：`setInterval(100ms)` 轮询 + 直接操作 DOM 文本节点，避免全量 re-render。

5. **词条展开/收起**：纯 UI 状态，存在 `UIManager`，不放入引擎。

#### 1b. ItemInstance 添加递归 children

```typescript
// data.ts & shared/types.ts
export interface ItemInstance {
  instanceId: string;
  defId: string;
  type: 'entity' | 'affix';
  children?: ItemInstance[];  // 容器内部的嵌套实体/词条
}
```

#### 1c. 新增递归辅助函数（data.ts）

- `getEffectiveEntitySlots(def: EntityDef, item?: ItemInstance): number`
  — 返回 `def.entitySlots + 容器词条加成`。容器词条取子项中最高级（覆写不叠加）。
- `flattenItemTree(item: ItemInstance): ItemInstance[]`
  — 递归展平自身及所有后代。
- `findInTree(item: ItemInstance, instanceId: string): ItemInstance | null`
  — 递归搜索。
- `countUsedSlots(parent: ItemInstance): number`
  — 计算直属子项中所有实体类子项的 slotCost 总和。

#### 1d. engine.ts — 冒险者自动部署

`resetState()` 中：

```typescript
// 旧：this.addToWarehouse(this.createItem('adventurer', 'entity'));
// 新：自动创建 deploySlot
const adv = this.createItem('adventurer', 'entity');
this.state.deploySlots.push({ entity: adv, children: [] });
```

#### 1e. engine.ts — 核心方法递归化

- **`findItem(instanceId)`**
  — 搜索路径扩展为：warehouse → deploySlots[].entity（递归） → deploySlots[].children（递归）。
- **`removeFromDeploy(instanceId)`**
  — 返回值改为 `{ slotIdx: number; parentInstanceId: string | null } | null`。
  — 从目标 parent 的 `children` 数组中 splice 删除。
- **`canEquipToSlot(slotIdx, parentId, childDef)`**
  — 签名新增 `parentId: string | null`。
  — null = 目标为 starter 直属；非 null = 在树中找该实体。
  — 校验：目标非 starter？目标剩余实体槽位 ≥ childDef.slotCost？
  — 实体槽位余量 = `getEffectiveEntitySlots(parentDef) - countUsedSlots(parent)`。
- **`moveToDeploy(item, slotIdx?, parentId?)`**
  — 支持嵌套目标：`parentId` 不为 null 时 push 到对应实体的 `children`。
- **`moveToWarehouse(item)`**
  — 使用递归 find + remove。
- **`sellItem(item)`**
  — 使用递归 find + remove。
- **`calculateCombatSnapshots()`**
  — 递归遍历所有嵌套层级，汇总 armorBonus / staminaRegenerationBonus / hpBonus / passiveDamageBonus / activeWeapons。
  — 递归伪代码：

```
function collectFromChildren(children: ItemInstance[]):
  for each child:
    if child.type === 'entity':
      def = getEntityDef(child.defId)
      if def.isActive:
        weapons.push({...child, damage + passiveBonus + growthStack})
      if !def.isActive:
        passiveBonus += def.damage
        armor += def.armorBonus
        regen += def.staminaRegenerationBonus
        hp += def.hpBonus
      if isContainer(child):
        recursively collectFromChildren(child.children)
    if child.type === 'affix':
      handle affix bonuses (strength, growth etc.)
```

#### 1f. panels.ts — 递归渲染

提取递归函数：

```
renderEntityTree(item: ItemInstance, depth: number, slotIdx: number, parentId: string | null): string
```

- 渲染实体行（`nested-${depth}` class）
- 若 `item.children?.length`：递归渲染每个子项（depth+1）
- 每个有 entitySlots 的实体渲染内嵌 drop zone（id 基于 instanceId）
- 词条子项也递归渲染（它们没有下层子项）

#### 1g. bindDeployDragEvents — 深层拖拽

- 每个实体行（有 entitySlots 的）都注册为 drop zone
- DragPayload 新增 `parentInstanceId` 字段
- 每层元素设为 draggable

#### 1h. DeploySlot 结构变化

保留原有 `DeploySlot = { entity: ItemInstance; children: ItemInstance[] }`。
启动端直属装备/词条仍在 `DeploySlot.children`。
容器实体的嵌套子项在 `DeploySlot.children[n].children`（即容器那个 ItemInstance 的 children）。

这样改动最小——现有代码只需在遍历 children 时额外检查容器实体的 children。

### Phase 4：战斗时间线引擎重构

**依赖**：Phase 1

#### 4a. 涉及文件

- `project/client/src/game/engine.ts`

#### 4b. 新增内部运行时类型

```typescript
interface CombatUnitRuntime {
  entityId: string;
  entityName: string;
  totalHp: number;
  currentHp: number;
  totalArmor: number;
  maxStamina: number;
  currentStamina: number;
  staminaRegen: number;       // 每秒回复
  isOverloaded: boolean;
  overloadPenalty: number;    // 1.0 或 1.5
  weapons: CombatWeaponRuntime[];
}

interface CombatWeaponRuntime {
  name: string;
  actionTime: number;
  remainingTime: number;      // 剩余触发时间 ms（每个 tick 扣减，到 0 触发）
  damage: number;
  staminaCost: number;
  attackType: string;
  attackOrder: string;
  priorityTarget: number | null;
}
```

#### 4c. runCombat 重写算法

```
async runCombat(onEvent, onUnitUpdate, onEnd, speed):
  playerUnits = CombatUnitSnapshot → CombatUnitRuntime[] (初始化 remainingTime)
  enemyUnits  = CombatUnitSnapshot → CombatUnitRuntime[] (同上)

  onUnitUpdate(playerUnits, enemyUnits)  // 初始展示

  while 双方都有存活单位 and 未超时:

    dt = min(所有武器.remainingTime)   // 下一次触发时间
    await sleep(dt / speed)           // 实际等待

    // 时间推进
    for each unit:
      unit.currentStamina = min(unit.currentStamina + unit.staminaRegen * dt / 1000, unit.maxStamina)

    for each weapon:
      weapon.remainingTime -= dt
      if weapon.remainingTime <= 0:
        if unit.currentStamina >= weapon.staminaCost * unit.overloadPenalty:
          // 触发！
          target = 选目标(weapon, enemyUnits)
          dmg = max(weapon.damage - target.totalArmor, 1)
          target.currentHp -= dmg
          unit.currentStamina -= weapon.staminaCost * unit.overloadPenalty
          weapon.remainingTime = weapon.actionTime
          onEvent({...})
        else:
          weapon.remainingTime = 0  // 下一 tick 耐力够了就触发

    onUnitUpdate(playerUnits, enemyUnits)  // 刷新显示

  onEnd(win, goldReward)
```

目标选择（按设计文档 05-战斗系统.md）：
- `priorityTarget ≠ null` → 优先攻击敌方该位置（存活检查）
- 否则按 `attackOrder` 搜索：`从上往下` → i=0..n，`从下往上` → i=n-1..0

#### 4d. 公开战斗状态

