# 探险阶段：商店货架 + 事件重设计 · 完整实现计划

> 日期：2026-08-14  
> 状态：已实现  
> 目标：限量货架 + 五事件（必出/可出）+ 备用资金池静默结算；取代旧整池商人与旧事件商人  
> 与 `design/01`、`02`、`DESIGN-正式局` 同步

## 一、定位与 Context

**现状问题**：固定商人整池开卖、事件全是变体商店，探险无「限量供给 + 刷新税」与差异化事件。

**目标**：常驻 6+3 货架（买一次消失、线性刷新费）；事件数据驱动出场；备用池承接阶段奖励；首发五事件可玩可存档。

**不介入**：战斗引擎、探险发金/胜奖公式数值、事件强度调参、通关强制清池。

## 二、核心抽象与规则

见 Cursor 计划共识（已确认）。摘要：

- 商店：`cost = 2 * (shopRefreshCount + 1)`；价值 cap = `round×10`；半价出售仅固定商店面板。
- 事件：N=3；必出优先占坑可突破 N；`mustAppearOn` / `canAppearOn` = 游戏奇数 round。
- 五事件出场：仅 hire must=`[1]`；invest can=`[1,3,5,7]`；其余 can=全部探险回合。
- `reserveGold`：胜奖/探险发放/投资回报入池；进探险静默结算；通关不清池。
- 点事件卡即锁定；开战收束进行中事件。

## 修改点详述（四段）

### 修改点 1：常驻商店货架

**现状**：整池可反复买同 def。  
**期望**：每探险 6 实体+3 词条实例货架；买一次移除；刷新线性费。  
**原因**：限量供给 + 金沉洞。  
**实现**：`engine.ts` roll/refresh/buyFromShop；`officialExplore`+`panels` 渲染刷新钮。

### 修改点 2：事件框架

**现状**：旧五种商人事件硬编码。  
**期望**：must/can、必出占坑、点卡锁定、done 态。  
**原因**：数据驱动出场。  
**实现**：`exploreEvents.ts` + `generateEvents`；UI 事件卡。

### 修改点 3：五事件内容

**现状**：无雇佣/走私新规则/工匠/打工/投资。  
**期望**：见共识各事件规则。工匠槽以 BD 式折叠卡片展示，可拖出换实体；七选一写入 overrides 后，槽位/HP/耐力/负重等须经 `getEffectiveValue`（及槽位 helpers）对构筑、卡片与战斗快照生效。  
**原因**：首发可玩集合；实例覆写不得被模板读路径吞掉。  
**实现**：engine 结算 API + panels；`getEffectiveEntitySlots` / `getEffectiveDynamicAffixSlots`；`calculateCombatSnapshots` / `computeStarterLoad` / entityCard·simTooltip 读 overrides；`extractCraftsmanItem` + 工匠卡片拖拽。

### 修改点 4：备用资金池

**现状**：探险/胜奖直接加 gold。  
**期望**：入 reserve，进探险静默结算；通关不清池。  
**原因**：统一延迟奖励与投资。  
**实现**：`addReserve` / `settleReserveWithGold`；改 `grantExploreGold` 路径与 `applyCombatVictoryRewards`。

### 修改点 5：design 同步

**现状**：文档仍写整池商人与旧事件。  
**期望**：货架/五事件/reserve。  
**原因**：机制真源。  
**实现**：改 `design/01` `02` `DESIGN-正式局`。
