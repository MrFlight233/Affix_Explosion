# 模拟对战页面设计优化

## Context

之前的"统一实体模型术语修正"已移除代码中"主动装备/被动装备"等互斥类型描述。但模拟对战页面的 UI 设计仍有遗留问题：

1. **物品池行**使用了分类标签和动作信息（`伤:X X.Xs`），过于冗长
2. **实体悬浮窗/卡片**仍使用 `getTypeBadges()` 显示"可触发/被动"标签——用户明确指出这些不是真正定义的实体类型
3. **悬浮窗结构**使用互斥三元（starter/survival, isActive/attack, !isActive/stats），信息分散且缺少独立的被动加成、词条、子实体分块

### 用户要求

1. 物品池：`名称  价10  槽耗1` 简洁格式
2. 实体悬浮窗：去除"主动/被动/可触发"标签，按**语义分块**：名称+价格同行 → 分类 → 基本信息 → 主动动作 → 被动加成 → 词条 → 子实体
3. 词条悬浮窗：名称+价格同行 → 分类 → 效果描述 → 基本信息 → 词条
4. **布局细节**：悬浮窗标题行 — 靠左名称，靠右价格（同一行）

## 修改文件清单

### A. `project/client/src/ui/sim-battle.ts` — 模拟对战专用 UI

#### A1. `getTypeBadges()` (L384-400)
- **移除** `if (def.isActive) tags.push('可触发')` 和 `if (!def.isActive) tags.push('被动')`
- 保留分类标签（`getEntityCategory`）和实例词条名

#### A2. `renderPoolEntityRow()` (L822-832)
- 改为：`名称  价${value}  槽耗${slotCost}`
- 移除分类名（`getEntityCategory(e).join(' / ')`）
- 移除主动动作信息（`伤:X X.Xs`）

#### A3. `renderTooltipTree()` (L402-509) — 实例树重构
三元互斥结构改为独立条件分块：名称+价格(外层header) → 分类 → 基本信息 → 主动动作 → 被动加成 → 词条 → 子实体

#### A4. `showSimTooltip()` (L525-640) — 外层重构
- Entity: Header 名称(左)+价格(右)同行，去掉 badges，分类在下
- Affix: Header 名称(左)+价格(右)同行 → 分类 → 效果 → 基本信息 → 词条

#### A5. `renderEntityCard()` (L974+) — 卡片微调
- Block 1 加入被动加成子块
- Block 3 加入前置词条/预装动态词条
- Block 4 加入预装子实体

#### A6. `renderCardKeyInfo()` (L876-953) — 折叠摘要行
保持三元结构，移除类型标签引用

### B. `project/client/src/ui/tooltip.ts` — 全局悬浮提示
- B1. renderEntityTooltip: 标题行名称(左)+价格(右) → 分类 → 基本信息 → 主动动作 → 被动加成 → 词条 → 子实体
- B2. renderAffixTooltip: 标题行名称(左)+价格(右) → 分类 → 效果 → 基本信息 → 词条

### C. `project/client/src/main.ts` — 管理员面板详情
- 被动加成条件从 `!isStarter && !isActive` 改为独立计算
- 加入前置词条显示

## 验证方式

1. 打开模拟对战页面，检查物品池行格式：`名称 价X 槽耗Y`
2. 悬停物品池中的实体，确认悬浮窗分块正确
3. 悬停出场区域的实体卡片，确认无"可触发/被动"标签
4. 悬停词条物品，确认悬浮窗分块正确
5. TypeScript 编译通过
