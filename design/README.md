# design/ 文档地图

> 本目录是游戏**机制与界面**的权威说明。增删改玩法或 UI 约定时，先改此处，再改代码。

## 与 doc/ 的边界

| 目录 | 放什么 |
|------|--------|
| **design/** | 现行游戏设计（机制真相 + UI 约定） |
| **doc/** | 更新说明、修改记录、AI 施工计划等**日志性**内容 |

- **design 内文档不得链接 `doc/`**（不引用计划/日志）。
- `doc/` 施工方案可指向 `design/` 落点以便落地；设计正文以本目录为准，不以 `doc/` 替代。

## 读写约定

1. **机制真相**在 `01`～`06`；**页面与组件**在 `07`～`08`。不要把玩法规则只写在 UI 文档里。
2. **事件**（`exploreEvents`、must/can、货架、文案）：必须同步 [06](./06-事件介绍.md)；[02](./02-名词解释.md) 摘要表字段变化一并改。
2b. **效果库 / 通道**（配方、引用、落点、合并）：必须同步 [09](./09-效果介绍.md)；[02](./02-名词解释.md)/[03](./03-实体介绍.md)/[04](./04-词条介绍.md)/[05](./05-战斗系统.md) 相关字段一并改。
3. 正式局界面细节以 [08](./08-正式局设计系统.md) 为准；[01](./01-游戏概述.md) 只保留流程级界面摘要。
4. 模拟战与正式局色值对齐：改 token 时同时核 [07](./07-模拟对战设计系统.md) 与 [08](./08-正式局设计系统.md)。
5. 机制变更落地后须反映到本目录对应文件；施工日志写在 `doc/`，不回写进 design 正文链接。
