## 词条属性定义


| 属性名                              | 类型  | 说明                                           |
| -------------------------------- | --- | -------------------------------------------- |
| 词条名称                             | 字符串 | 词条的唯一名称                                      |
| 类别                               | 枚举  | 属性 / 行动 / 伤害 / 防御 / 耐力 / 负重 / 限制 / 特殊 / 实体分类 |
| 初始价值                             | 自然数 | 购买/出售基准价（`costValue`）                         |
| 动态价值                             | 自然数 | 当前价值                                         |
| 占有槽位(slotCost)                      | 自然数（含 0） | 占用动态词条槽位，默认 1；**0 表示不占用**           |
| 是否可重复                            | 布尔  | 同一实体上能否叠加多个                                  |
| 放置前置词条                           | 列表  | 实体现有词条要求                                     |
| 物品池前置词条                          | 列表  | 解锁到物品池的条件                                    |
| 特殊效果                             | 字符串 | 词条的具体效果描述                                    |
| 命中效果                             | 列表  | 数值变化管道（displayName/stat/op/params/applyTo），与实体同结构 |
| 被动效果 / 被动目标 | 同实体 | 存在维持；聚合到第一层实体（不限 starter） |
| 被动加成总开关(hasPassiveBonuses) | 布尔 | false → 跳过 |

### 被动加成生效范围

- ✅ 挂在第一层实体子树任意位置 → 聚合到该第一层实体（含木桩）
- ❌ 仓库中 → 不生效
- 规范：动态过滤慎挂上限类；非「仅根实体」须注明由第一层维持、阵亡失效

详见 [doc/2026-08-04-被动加成目标与存在生效.md](../doc/2026-08-04-被动加成目标与存在生效.md)。

## 词条分类体系

词条按类别组织，每种类别有不同作用：


| 类别 | 典型作用 |
|------|----------|
| 属性 | 数值类被动加成（伤害、回复、HP、耐力相关数值等） |
| 行动 | 与行动节奏/触发相关的效果（以实际已实现词条为准） |
| 伤害 | 伤害向效果（以已实现为准，如命中效果类可挂此分类） |
| 防御 | 生存向效果（以已实现为准；**无护甲减伤机制**） |
| 耐力 | 耐力系统调节（上限、回复、消耗） |
| 负重 | 负重系统调节（上限、轻量化） |
| 限制 | 约束/条件类效果 |
| 特殊 | 特殊机制（如生命偷取等已实现效果） |
| 目标修改 | 覆写武器目标选择（`targeting_modifier`） |
| 实体分类 | 实体分类标记（`starter`、`weapon_type`、`armor_type`、`accessory_type` 等）——零价值零槽位，仅用于分类识别 |

> 已删除未实现机制在文档中的示例（连击、反击、中毒、闪避、护甲、成长、follower 等）。类别本身可由管理员配置；上表只描述与现行战斗设计一致的方向。

### 词条依赖关系

部分词条有**前置词条**（`AffixDef.prerequisite`）要求。例如：挂载「负重训练」前，同一实体须已有「战士」。

**构筑校验（模拟战 BD、正式局 BD / 仓库挂载与卸下）：**

- **挂载**：目标实体「已有词条」= 固定词条（`overrides.fixedAffixes` 优先，否则模板 `fixedAffixes`）+ 动态词条子项；须满足全部前置。缺则拒绝并提示「需要前置词条：…」。
- **卸下 / 迁走**：若同实体上仍有其它动态词条依赖该词条，拒绝并提示「不可移除「X」：A、B 依赖此词条」。
- **制作物品（Admin）**不做此限制（模板编辑自由）。

另有**物品池前置**（`poolPrerequisite`）：控制商店/池解锁，与放置前置无关。

### 分类管理

词条的分类（类别字段）由 `categories` 表驱动，管理员可在管理后台的「管理分类」弹窗中增删改查。每个分类有：

- **id**：代码标识（如 `attribute`、`entity_class`），用于代码判断
- **name**：显示名（如「属性」「实体分类」），用于 UI 展示
- **is_entity_class**：标记该分类是否为实体分类标记（原「类别」分类的角色）

`entity_class` 分类下的词条作为实体类型标记，实体的 `fixedAffixes` 中包含这类词条时，`getEntityCategory()` 自动推导其实体类型。

管理员可在制作物品页面自由创建和调整词条模板。

## 命中效果词条

命中效果在 `onHitEffects` 中配置，结构与实体相同（`displayName` / `stat` / `op` / `params` / `applyTo`）。

- 挂在武器上 → 仅该武器；挂在启动端上 → 该启动端全部主动。
- 示例：吸血 = `stat:hp, op:gain, applyTo:['starter']`；削耐 = `stat:stamina, op:loss`（默认 target）。
- 词条卡/悬浮用「主动效果」块展示 `onHitEffects`，行文案与实体主动效果块相同（见主动动作三块展示）。Admin 分区见 [doc/2026-08-05-词条分区展示对齐.md](../doc/2026-08-05-词条分区展示对齐.md)。

详见 [05-战斗系统](./05-战斗系统.md) §4.4、[doc/2026-08-03-命中效果管道化.md](../doc/2026-08-03-命中效果管道化.md)、[doc/2026-08-03-主动动作三块展示.md](../doc/2026-08-03-主动动作三块展示.md)。

## 主动目标覆写（targeting_modifier）（v8）

产品用语：**主动目标覆写**。`targeting_modifier` 通过 `targetingModifier` 覆写挂载实体的主动选目标：**阵营 / 统一排序 / 多选过滤 / 目标数量**。

### TargetingModifier 接口（v8）

```typescript
interface TargetingModifier {
  sortBy?: string | null;                 // 统一排序；null=清除
  filterBy?: string | string[];           // 多选过滤（含阵营）；有值=覆写；省略=不修改（不再用 null 清除）
  targetCount?: number | 'all' | null;    // 取 N / 全部；null=清除为默认1
}
```

- 默认 **"不修改"**（undefined）；`sortBy` / `targetCount` 的 `null` = 清除该字段
- `filterBy`：Admin 仅支持「有值覆写 / 省略不修改」；历史本地数据若仍有 `null` 引擎可读作空数组，但不作为正式配置
- 已移除对 `targetFaction` / `targetOrder` / `priorityTarget` 的配置；旧数据读档时映射进 `filterBy` / `sortBy`

### 主开关

- **"不修改"** → 不保存 `targetingModifier`，子字段隐藏
- **"修改"** → 显示可覆写项，各项可「不修改」

### 生效范围 / 合并

Per-Entity；children 从前到后浅合并。详见 [05-战斗系统](./05-战斗系统.md)。

### 示例词条

| 词条ID | 名称 | targetingModifier | 说明 |
|--------|------|-------------------|------|
| `affix_smart_tracking` | 智能追踪 | `{ sortBy: 'hp_asc' }` | 打 HP 绝对值最低 |
| `affix_frenzy` | 狂乱 | `{ sortBy: 'random' }` | 随机 |
| `affix_weakness_sense` | 弱点感知 | `{ filterBy: ['has_debuff'] }` | **预留** debuff（Admin 条件行不暴露 `has_debuff`/`most_buffs`；战斗未维护对应状态） |
| `affix_healer_targeting` | 治疗引导 | `{ filterBy: ['友方'], sortBy: 'hp_pct_asc' }` | 友方 HP% 最低；治疗需 `damage < 0` |
| `affix_friendly_fire` | 友军火力 | `{ filterBy: ['友方','敌人'], sortBy: 'random', targetCount: 1 }` | 合并池随机 1 |
| `affix_cleave_center` | 中心挥击 | `{ filterBy: ['敌人'], sortBy: '站位中间', targetCount: 3 }` | 中心扩散 3 目标 |

### 设计意图

- 同一武器挂不同 targeting 词条 → Build 组合乐趣
- 多目标 / 百分比排序更强时用 damage、actionTime、`costValue` 平衡

## 被动加成总开关（hasPassiveBonuses）

词条与实体表单的「被动加成」区均有整体主开关：被动模式 + 被动目标 + 效果列表（与主动同构、无耐耗/耗时）。

### 主开关逻辑

- **"无"** → `hasPassiveBonuses = false`：隐藏并清零；引擎跳过采集
- **"有"** → `hasPassiveBonuses = true`：编辑目标与效果；聚合到第一层实体后维持

### 数据兼容

- 旧五列非零 → 迁入 `passiveEffects`，默认目标「根实体」×1
- 新建默认 `has_passive_bonuses = 0`（无）
