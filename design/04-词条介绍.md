## 词条属性定义


| 属性名                              | 类型  | 说明                                           |
| -------------------------------- | --- | -------------------------------------------- |
| 词条名称                             | 字符串 | 词条的唯一名称                                      |
| 类别                               | 枚举  | 属性 / 行动 / 伤害 / 防御 / 耐力 / 负重 / 限制 / 特殊 / 实体分类 |
| 初始数值                             | 自然数 | 基础数值                                         |
| 动态数值                             | 自然数 | 受其他效果影响后的当前值                                 |
| 初始价值                             | 自然数 | 购买/出售基准价                                     |
| 动态价值                             | 自然数 | 当前价值                                         |
| 占有槽位                             | 自然数 | 占用槽位，默认 1                                    |
| 是否可重复                            | 布尔  | 同一实体上能否叠加多个                                  |
| 放置前置词条                           | 列表  | 实体现有词条要求                                     |
| 物品池前置词条                          | 列表  | 解锁到物品池的条件                                    |
| 特殊效果                             | 字符串 | 词条的具体效果描述                                    |
| 命中效果                             | 列表  | 武器命中正伤害后触发的额外效果（v5.2 新增）                     |
| 伤害加成(damageBonus)                | 整数  | 被动加成：全局伤害加成(正=增伤,负=增强治疗)                     |
| 生命加成(hpBonus)                    | 整数  | 被动加成：为启动端增加生命上限                              |
| 生命恢复加成(hpRegenerationBonus)      | 整数  | 被动加成：每秒额外恢复生命值                               |
| 耐力加成(staminaBonus)               | 整数  | 被动加成：为启动端增加耐力上限                              |
| 耐力恢复加成(staminaRegenerationBonus) | 整数  | 被动加成：每秒额外恢复耐力值                               |


### 被动加成生效范围

词条被动加成与实体被动加成一致：**向上聚合到最近的启动端 (starter)**。

- ✅ 挂载在启动端子树的任意位置（直属词条槽、武器/防具/饰品的动态词条槽）→ 聚合到该启动端
- ❌ 挂载在非启动端（木桩）子树中 → 不生效（木桩不执行被动聚合）
- ❌ 存放于仓库中 → 不生效

详见 [02-名词解释](./02-名词解释.md) 中「被动加成」公式汇总。

## 词条分类体系

词条按类别组织，每种类别有不同作用：


| 类别   | 典型作用                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| 属性   | 数值加成（伤害、速度、回复、HP）                                                              |
| 行动   | 行为触发（独立行动、连击、反击、先攻）                                                            |
| 伤害   | 伤害附加（元素伤害、中毒、debuff）                                                           |
| 防御   | 伤害减免（魔抗、闪避）                                                                    |
| 耐力   | 耐力系统调节（上限、回复、消耗）                                                               |
| 负重   | 负重系统调节（上限、轻量化）                                                                 |
| 限制   | 约束/条件类效果                                                                       |
| 特殊   | 特殊机制（吸血、成长、幸运、荆棘）                                                              |
| 目标修改 | （v6 新增）覆写武器的目标选择行为（targeting_modifier）— 改变条件排序、过滤等                                 |
| 实体分类 | 实体分类标记（starter、follower、weapon_type、armor_type、accessory_type）——零价值零槽位，仅用于分类识别 |


### 词条依赖关系

部分词条有**前置词条**要求。例如：

- 行动类：连击/反击/先攻 需要 starter
- 防御类：闪避 需要 敏捷
- 部分武器类实体有**池前置词条**（如需要力量/智力解锁到物品池）

### 分类管理

词条的分类（类别字段）由 `categories` 表驱动，管理员可在管理后台的「管理分类」弹窗中增删改查。每个分类有：

- **id**：代码标识（如 `attribute`、`entity_class`），用于代码判断
- **name**：显示名（如「属性」「实体分类」），用于 UI 展示
- **is_entity_class**：标记该分类是否为实体分类标记（原「类别」分类的角色）

`entity_class` 分类下的词条作为实体类型标记，实体的 `fixedAffixes` 中包含这类词条时，`getEntityCategory()` 自动推导其实体类型。

管理员可在制作物品页面自由创建和调整词条模板。

## 命中效果词条（v5.2 新增）

命中效果词条在 `onHitEffects` 字段中配置。武器造成正伤害后自动触发。


| 词条ID          | 名称   | 命中效果                                               | 说明                                                           |
| ------------- | ---- | -------------------------------------------------- | ------------------------------------------------------------ |
| life_steal    | 生命偷取 | `type: life_steal, params: { percent, amount }`    | 命中回复启动端 HP。效果始终只对挂载实体的动作生效；挂 starter 时因传播规则也影响子树 isActive 实体 |
| stamina_drain | 耐力削弱 | `type: stamina_drain, params: { percent, amount }` | 命中削减被命中方耐力。效果始终只对挂载实体的动作生效；挂 starter 时同理传播                   |

## Targeting 覆写词条（targeting_modifier）（v7 扩展）

`targeting_modifier` 分类的词条通过 `targetingModifier` 字段覆写挂载实体的 **全部 5 个 targeting 字段**（v6 仅支持 sortBy/filterBy）。

### TargetingModifier 接口（v7）

```typescript
interface TargetingModifier {
  targetFaction?: TargetFaction | null;   // 覆写针对目标
  targetOrder?: string | null;            // 覆写针对顺序
  priorityTarget?: number | null;         // 覆写优先目标位
  sortBy?: TargetSortBy;                  // 覆写条件排序
  filterBy?: TargetFilterBy;              // 覆写条件过滤
}
```

- 每个字段默认值为 **"不修改"**（= undefined），不参与覆写
- 字段值为 `null` 表示**清除该字段**（设为无值，如清除 priorityTarget）
- 只有明确设置了值的字段才参与覆写

### 主开关

词条表单中有一个整体「覆写模式」开关：
- **"不修改"** → `targetingModifier` 不保存（undefined），5 个子字段隐藏
- **"修改"** → 显示 5 个子字段，各有独立的「不修改」选项

### 生效范围（Per-Entity）

- 词条的 targeting_modifier **只影响其直属实体**的武器
- 不影响同父实体的兄弟实体武器
- 不影响父实体或更上层的武器

### 合并顺序

当一个实体挂载多个 targeting_modifier 词条时，按**实体 children 数组从前到后**依次合并。
后遍历的词条字段覆盖先遍历的（最后的值胜出）。详见 [05-战斗系统](./05-战斗系统.md)「3.4.4 覆写合并顺序」。

### 示例词条

| 词条ID | 名称 | targetingModifier | 说明 |
|--------|------|-------------------|------|
| `affix_smart_tracking` | 智能追踪 | `{ sortBy: 'hp_asc' }` | 该武器总是攻击 HP 最低的敌人 |
| `affix_frenzy` | 狂乱 | `{ sortBy: 'random' }` | 该武器随机攻击目标 |
| `affix_weakness_sense` | 弱点感知 | `{ filterBy: 'has_debuff' }` | 该武器优先攻击有负面状态的目标 |
| `affix_healer_targeting` | 治疗引导 | `{ targetFaction: '友方', sortBy: 'hp_asc' }` | 该武器改为治疗 HP 最低的友方 |
| `affix_friendly_fire` | 友军火力 | `{ targetFaction: '所有', sortBy: 'random' }` | 随机攻击任意目标（包括友方） |

### 设计意图

- 同一个武器通过挂不同 targeting 词条，行为完全不同——这是 **Build 组合的核心乐趣**
- targeting_modifier 词条的 value 应反映其强度（智能追踪 > 狂乱）
- 条件 Targeting 武器可能比位置 Targeting 武器更强，可通过 damage 或 actionTime 平衡

## 被动加成总开关（hasPassiveBonuses）（v7 新增）

词条表单的「被动加成」区有一个整体主开关：

```
┌─ 被动加成 ──────────────────────────┐
│ 被动加成模式: [无 ▼] / [有 ▼]        │
│                                      │
│ (当选择「有」时显示以下字段)           │
│                                      │
│ 伤害加成: [____]                     │
│ 生命加成: [____]                     │
│ 生命恢复加成: [____]                 │
│ 耐力加成: [____]                     │
│ 耐力恢复加成: [____]                 │
└──────────────────────────────────────┘
```

### 主开关逻辑

- **"无"** → `hasPassiveBonuses = false`
  - 5 个被动字段隐藏
  - 保存时所有被动值自动清零（避免残留旧值）
  - 引擎在构建战斗快照时**完全跳过**该词条的被动字段读取——性能优化
- **"有"** → `hasPassiveBonuses = true`
  - 5 个被动字段显示并可编辑
  - 引擎正常读取并聚合该词条的被动加成

### 设计意图

- 大量词条（targeting_modifier、命中效果类、特殊类）无需被动加成
- 用 `hasPassiveBonuses` 快速筛选，避免逐字段检查零值——引擎高性能
- 为用户提供明确的"这个词条有/没有被动加成"的视觉判断

### 数据兼容

- 旧词条通过数据库迁移自动回填：任何被动字段非零 → `has_passive_bonuses = 1`
- 新建词条默认 `has_passive_bonuses = 0`（无）
