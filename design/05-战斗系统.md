# 05 - 战斗系统

> 相关文档：[01-游戏概述](./01-游戏概述.md) | [02-名词解释](./02-名词解释.md) | [03-实体介绍](./03-实体介绍.md) | [04-词条介绍](./04-词条介绍.md)

## 概述

战斗系统采用**基于时间线的全自动回合制**。核心机制：
- **耐力系统**：控制可触发动作的触发频率
- **负重系统**：超重惩罚耐力消耗
- **针对系统**：近战/远程的目标选择 + 针对目标（友方/敌人/所有）
- **无护甲**：伤害 = weaponDamage，直接扣减 HP

## 一、战斗前准备

### 1.1 第一层级检查
- 战斗开始时，扫描出场面板，识别所有**第一层级**的实体。
- 拥有 `starter` 词条的实体加入行动时间线。
- 无 `starter` 的实体放在第一层 = 木桩（有 HP 可被攻击，不触发动作）。
- **验证规则**：拥有 `starter` 词条的实体不允许放在非第一层级。

### 1.2 第一层槽位检查
- 第一层槽位数 = 当前回合数（round）。
- 所有第一层实体的 `slotCost` 之和 ≤ 第一层槽位数。
- 超出时无法开始战斗。

### 1.3 构建战斗数据
对每个 starter 实体，汇总自身属性 + 所有子孙实体的属性：

| 汇总属性 | 计算方式 |
|----------|----------|
| 总生命值 | 自身 HP + 自身生命加成 + Σ(子孙实体生命加成) |
| 总生命恢复 | 自身 hpRegen + 自身生命恢复加成 + Σ(子孙实体生命恢复加成) |
| 总耐力上限 | 自身 maxStamina + 自身耐力加成 + Σ(子孙实体耐力加成) |
| 总耐力恢复 | 自身 staminaRegen + 自身耐力恢复加成 + Σ(子孙实体耐力恢复加成) |
| 当前负重 | Σ(所有子孙实体重量) |
| 负重上限 | 自身 maxLoad |
| 可触发动作列表 | 自身 isActive + 收集所有子孙中 isActive=true 的实体 |

**启动端自身动作**：当启动端实体自身的 `isActive=true` 时，其自身作为一个可触发动作加入时间线：
- 武器名称 = 启动端实体名称
- 使用启动端自身的 damage / actionTime / staminaCost / targetType / targetOrder / priorityTarget / targetFaction
- 耐力消耗从启动端自身的耐力池扣除，受到超重惩罚（+50%）
- 受到被动装备的伤害加成（与其他子武器相同）
- 在武器列表中排在第一位（子实体武器之前）

### 1.4 超重判定
```
if 当前负重 > 负重上限:
    超重状态 = true
    该实体下所有可触发动作 staminaCost × 1.5
else:
    超重状态 = false
```

## 二、战斗进行

### 2.1 时间线模型

战斗使用**固定时间步长**（100ms / tick）。引擎每 100ms 推进一次，全局时间统一前进：

```
时间线（全局统一，每 100ms 一帧）:
  Tick 0   (0ms):    所有武器 init（remainingTime = actionTime）
  Tick 1   (100ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  Tick 2   (200ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  ...
  Tick 20  (2000ms): 短剑 cd=2000ms 到期，触发！
```

- 同一个 tick 内可能有**多把武器同时触发**，按玩家→敌人、武器列表顺序依次处理。
- 先触发的武器击杀目标后，后续武器通过目标存活检查自动跳过已死亡单位。

### 2.2 行动流程（每个 tick 内）

```
每个 tick (100ms):
         │
         ▼
  ┌─────────────────────────┐
  │ 恢复所有单位的 HP 和耐力   │
  │ 所有武器 remainingTime    │
  │ 递减 100ms               │
  └──────────┬──────────────┘
             │
             ▼
  ┌─────────────────────────┐
  │ 遍历所有武器              │
  │ remainingTime ≤ 0 ?      │
  └──────────┬──────────────┘
             │
    ┌────────┴────────┐
    │ 否              │ 是
    ▼                 ▼
  ┌──────────┐   ┌─────────────────────────┐
  │ 跳过      │   │ 检查当前耐力              │
  └──────────┘   └──────────┬──────────────┘
                            │
                   ┌────────┴────────┐
                   │ 足够            │ 不足
                   ▼                 ▼
             ┌──────────┐   ┌──────────────────┐
             │ 立即行动  │   │ remainingTime = 0  │
             │ 扣除耐力  │   │ 下个 tick 再试      │
             └─────┬────┘   └──────────────────┘
                   ▼
  ┌─────────────────────────────┐
  │ 执行动作:                    │
  │ 1. 按 targetFaction 选目标   │
  │ 2. 按 targetType/targetOrder │
  │    选具体目标                 │
  │ 3. dmg = weaponDamage       │
  │ 4. 目标 HP -= dmg            │
  │    （正=伤害, 负=恢复）       │
  └──────────────┬──────────────┘
                 ▼
  ┌─────────────────────────────┐
  │ 重置倒计时:                  │
  │ remainingTime = actionTime   │
  └─────────────────────────────┘
```

### 2.3 耐力恢复机制

耐力在战斗中**持续每秒恢复**。

```
耐力恢复公式:
  当前耐力 = min(当前耐力 + 总耐力恢复速度 × 时间增量, 耐力上限)
```

### 2.4 生命恢复机制

生命在战斗中**持续每秒恢复**（仅当总生命恢复 > 0 时生效）。

```
生命恢复公式:
  当前生命 = min(当前生命 + 总生命恢复速度 × 时间增量, 总生命值)
```

**并行触发机制：**
- 同一 tick 内多把武器按顺序独立触发。
- 耐力不足的武器搁置到下个 tick（100ms 后）重试。
- 死亡单位的武器不再触发。

## 三、针对系统

### 3.1 针对目标（targetFaction）

决定动作的对付对象：

| 值 | 说明 |
|----|------|
| 友方 | 只在己方单位中选目标 |
| 敌人 | 只在敌方单位中选目标 |
| 所有 | 同时搜索双方，各自按顺序选目标 |

### 3.2 针对类型（targetType）与针对顺序（targetOrder）

| 属性 | 说明 | 可选值 |
|------|------|--------|
| 针对类型 | 搜索策略 | 近战 / 远程 |
| 针对顺序 | 兜底搜索方向 | 从上往下 / 从下往上 |
| 优先目标位 | 优先攻击第几位 | 1 / 2 / 3 / null |

### 3.3 目标选择逻辑

```
1. 按 targetFaction 筛选候选池
2. 优先目标位 != null → 检查该位置是否有存活实体
   ├─ 有 → 攻击该位置
   └─ 无 → 进入步骤 3
3. 按针对顺序方向搜索最近的存活实体
   ├─ 从上往下：从 [0] 开始向下搜索
   └─ 从下往上：从末尾开始向上搜索
4. 候选池全部死亡 → 跳过该动作
```

### 3.4 类型默认约定

| 类型 | 针对顺序 | 优先目标位 | 说明 |
|------|----------|------------|------|
| 近战（默认） | 从上往下 | 1 | 固定打前排第一位 |
| 远程（默认） | 从下往上 | null | 从后排往前搜索 |

### 3.5 多可触发实体的独立目标选择

每个可触发实体**独立选目标**，即使同一父实体下的多个武器也可攻击不同目标。

```
冒险者拥有：
  ├── 短剑（针对敌人, 近战, 从上往下, 优先1）→ 攻击敌方 [0]
  └── 法杖（针对敌人, 远程, 从下往上, 优先3）→ 攻击敌方 [2]

每次独立触发，各自选目标！
```

## 四、伤害计算

### 4.1 伤害公式

```
dmg = weaponDamage
```

- 正 = 伤害（扣减目标 HP）。
- 负 = 恢复（增加目标 HP），**不可超过目标 HP 上限**。
- 零 = 无效果。
- **无最小值限制**，伤害可以为 0 或负值。
- **无护甲减伤**，直接扣减。
- **HP 上限保护**：恢复类动作（负伤害）受 HP 上限约束，`HP = min(HP, maxHP)`。

### 4.2 针对目标与伤害的交互

| targetFaction | 正伤害 | 负伤害 |
|---------------|--------|--------|
| 敌人 | 攻击敌方 | 恢复敌方 |
| 友方 | 攻击友方 | 恢复友方 |
| 所有 | 双方各扣 | 双方各恢复 |

### 4.3 计算示例

```
短剑（伤害 5, 针对目标=敌人）攻击敌方前排
  → dmg = 5, 敌方 HP -5

治疗杖（伤害 -10, 针对目标=友方, 针对顺序=从上往下）恢复己方第一位
  → dmg = -10, 己方 HP +10

震荡波（伤害 3, 针对目标=所有）同时攻击双方
  → 敌方每位各扣 3 HP, 己方每位各扣 3 HP
```

## 五、死亡与复活

### 5.1 死亡
- HP ≤ 0 → 实体死亡。
- 死亡实体的武器不再触发，倒计时停止。
- 死亡实体的子孙实体退出战斗。

### 5.2 复活
- HP 恢复到 > 0 → 实体复活。
- 重新加入战斗，武器重新开始计时。

### 5.3 胜负条件
- **胜利**：敌方所有第一层实体 HP ≤ 0。
- **失败**：玩家方所有第一层实体 HP ≤ 0。
- **双方同灭**：玩家胜利。
- **120 秒上限到达**：玩家胜利。
- 详见「六、超时惩罚」。

## 六、超时惩罚

### 6.1 机制

战斗进行到 **60 秒** 后，进入软狂暴阶段。每秒对**双方所有第一层实体**造成一次递增伤害。

### 6.2 伤害公式

```
overtimeSeconds = floor((simTime - 60000) / 1000)   // 第1秒=1, 第2秒=2, ...
penaltyDamage   = overtimeSeconds × 10              // 10, 20, 30, ...
```

| 时间 | 伤害 | 累计 |
|------|------|------|
| 61s  | 10   | 10   |
| 62s  | 20   | 30   |
| 63s  | 30   | 60   |
| 64s  | 40   | 100  |
| 70s  | 100  | 550  |
| 120s | 600  | 18300 |

### 6.3 胜负判定

- 敌方全灭 → 玩家胜利
- 双方同时全灭 → 玩家胜利
- 120 秒上限到达 → 玩家胜利
- 仅玩家方全灭而敌方仍有存活 → 玩家失败

### 6.4 设计意图

- 防止纯恢复型 BD 导致战斗无法结束
- 递增伤害给双方施加越来越大的压力，强制分出胜负
- 120 秒时若仍未结束，判定玩家胜利

## 七、战斗结算

### 7.1 奖励

| 奖励项 | 计算方式 |
|--------|----------|
| 基础金币 | `10 + round × 5 + 出场槽位数 × 2` |
| 物品掉落 | 无（战斗获胜只给金币） |

### 7.2 失败处理
- 游戏结束，从最近的自动存档重试。

## 九、敌方来源

敌方有两种来源，按优先级排列：

### 9.1 在线对战池（优先）

玩家进入战斗阶段时，BD 自动上传到对战池，同时从池中随机抽取其他玩家的 BD 作为对手。

- **匹配规则**：同回合（round），随机抽取 1 个
- **不计算战力、不统计战绩、不分楼层**：对战池是纯粹的 BD 交换市场
- **池空处理**：对战池无对手或网络异常时，自动获胜（视为胜利，正常发放奖励）

详见 `doc/在线对战池-待实现.md`。

### 9.2 自动获胜（池空兜底）

当对战池中无可用对手时，系统直接判定玩家自动获胜，正常发放金币和 growth 奖励，不进入战斗引擎。

> 注：`generateEnemyBD()` 硬编码模板已不再被 `runCombat()` 调用，仅保留供参考或后续测试使用。

## 十、平衡参考

### 10.1 战斗时长目标
| 轮次 | 目标时长 | 说明 |
|------|----------|------|
| 回合 2 | 15~30 秒 | 教学，玩家基础 BD 可通过 |
| 回合 4 | 25~50 秒 | 需要一定的词条搭配 |
| 回合 6 | 40~80 秒 | 需要较完整的 BD 体系 |

### 10.2 耐力平衡参考
- 高频武器（匕首、短剑）：低耐力消耗，适合持续输出。
- 低频武器（战锤、法杖）：高耐力消耗，需要耐力强化词条支撑。
- 超重惩罚：+50% 耐力消耗，明显痛感但不至于完全无法战斗。

### 10.3 针对类型平衡
- 近战：稳定打前排，需要足够伤害快速击破肉盾。
- 远程：可绕过前排打后排，先消灭高输出低 HP 的远程敌人可降低承伤。
