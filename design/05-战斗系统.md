## 概述

战斗系统采用**基于时间线的全自动回合制**。核心机制：
- **耐力系统**：控制可触发动作的触发频率
- **负重系统**：超重惩罚耐力消耗
- **针对系统**：近战/远程的目标选择 + 针对目标（友方/敌人/所有）
- **无护甲**：伤害 = weaponDamage，直接扣减 HP

## 一、战斗前准备

### 1.0 正式战匹配与开战（客户端流程）

正式战斗与模拟战斗共用同一演算引擎与同一播放控件；差异仅在 BD 来源与战后结算。

**正式战顺序：**

1. 上传己方出场 BD 到对战池  
2. 从对战池抽取敌方 BD（空池则标记自动获胜）  
3. 立即开战或结算；抽取后**不再二次抽池**  
4. 战斗中可使用与模拟战相同的暂停 / 倍速（1x·2x·4x·Max）播放控制  

**模拟战：** 双方 BD 均为自建；播放控件与正式战共用模块。

### 1.1 第一层级检查
- 战斗开始时，扫描出场面板，识别所有**第一层级**的实体。
- 拥有 `starter` 词条的实体加入行动时间线。
- 无 `starter` 的实体放在第一层 = 木桩（有 HP 可被攻击，不触发动作）。
- **验证规则**：拥有 `starter` 词条的实体不允许放在非第一层级。

### 1.2 第一层槽位检查
- 第一层槽位数 = 当前回合数（round）。
- 所有第一层实体的 `slotCost` 之和 ≤ 第一层槽位数。
- 超出时无法开始战斗。

### 1.3 构建战斗数据
对每个 starter 实体，汇总自身属性 + 所有子孙实体的属性：

| 汇总属性 | 计算方式 |
|----------|----------|
| 总生命值 | 自身 HP + 自身生命加成 + Σ(子孙实体生命加成) |
| 总生命恢复 | 自身 hpRegen + 自身生命恢复加成 + Σ(子孙实体生命恢复加成) |
| 总耐力上限 | 自身 maxStamina + 自身耐力加成 + Σ(子孙实体耐力加成) |
| 总耐力恢复 | 自身 staminaRegen + 自身耐力恢复加成 + Σ(子孙实体耐力恢复加成) |
| 当前负重 | Σ(所有子孙实体重量) |
| 负重上限 | 自身 maxLoad + Σ(子树实体/词条 loadBonus)（含自身，受 hasPassiveBonuses） |
| 被动伤害加成 | Σ(子孙实体/词条的 damageBonus，受 hasPassiveBonuses) |
| 可触发动作列表 | 自身 isActive + 收集所有子孙中 isActive=true 的实体 |

**启动端自身动作**：当启动端实体自身的 `isActive=true` 时，其自身作为一个可触发动作加入时间线：
- 武器名称 = 启动端实体名称
- 使用启动端自身的 damage / actionTime / staminaCost / targetType / targetOrder / priorityTarget / targetFaction
- 耐力消耗从启动端自身的耐力池扣除，受到超重惩罚（+50%）
- 受到子孙实体的伤害加成（与其他子武器相同）
- 在武器列表中排在第一位（子实体武器之前）

### 1.4 被动伤害加成

**定义**：实体的 `damageBonus` 字段是一个独立于 `isActive` 的被动伤害加成——一个全局被动值，会加至父启动端的所有可触发武器上。

**聚合规则**：
- 递归遍历启动端的所有子孙实体（包括启动端自身）
- 每个 `hasPassiveBonuses` 的实体 → `passiveDamageBonus += entity.damageBonus`（`isActive=false` 时）
- 每个 `hasPassiveBonuses` 的词条 → `passiveDamageBonus += affix.damageBonus`
- 该实体自身的子孙继续递归，其 `passiveDamageBonus` 也向上累加

**符号匹配（v5.1 新增）**：
- 正的伤害加成（+N）只影响基础伤害为正的武器——增伤配件不会弱化治疗效果
- 负的伤害加成（-N）只影响基础伤害为负的武器（治疗武器）——诅咒配件不会削弱输出
- 零伤害加成无效果

**生效范围**：
- 影响父启动端的**所有子孙实体**中 `isActive=true` 的实体的武器伤害
- 包括启动端自身的主动动作（如果启动端 `isActive=true`）
- 不影响其他启动端——每个启动端的 `passiveDamageBonus` 独立计算

**示例**：
```
冒险者（starter, isActive=true, damage=10）装备:
  ├── 力量戒指（damageBonus=+5）  ← 被动伤害加成，独立于 isActive
  └── 吸血匕首（isActive=true, damage=-8）   ← 治疗武器

计算结果:
  - 冒险者自身武器: damage=10（正伤害），收到 +5 加成 → 最终 15
  - 吸血匕首: damage=-8（负伤害/治疗），+5 加成不匹配符号 → 保持 -8
  - 如果力量戒指 damageBonus=-3: 冒险者武器不受影响（正不匹配负），吸血匕首变为 -11（增强治疗）
```

### 1.5 超重判定
```
有效负重上限 = maxLoad + ΣloadBonus（子树实体/词条，含启动端自身，受 hasPassiveBonuses）
if 当前负重 > 有效负重上限:
    超重状态 = true
    该实体下所有可触发动作 staminaCost × 1.5
else:
    超重状态 = false
```

## 二、战斗进行

### 2.1 时间线模型

战斗使用**固定时间步长**（100ms / tick）。逻辑上每 100ms 推进一帧，全局时间统一前进：

```
时间线（全局统一，每 100ms 一帧）:
  Tick 0   (0ms):    所有武器 init（remainingTime = actionTime）
  Tick 1   (100ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  Tick 2   (200ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  ...
  Tick 20  (2000ms): 短剑 cd=2000ms 到期，触发！
```

- 同一个 tick 内可能有**多把武器同时触发**，按玩家→敌人、武器列表顺序依次处理。
- 先触发的武器击杀目标后，后续武器通过目标存活检查自动跳过已死亡单位。

#### 演算与播放分离（实现层）

客户端将战斗拆为两层（不影响上表逻辑规则）：

| 层 | 职责 |
|----|------|
| **BattleSimulator（演算）** | 同步 `step()` / `runToEnd()`，无墙钟等待；事件写入缓冲 |
| **Playback（播放）** | 按倍速（1x / 2x / 4x / Max）消费步进或回放；暂停/取消只影响播放 |

约定：

- **逻辑 tick 仍为 100ms**；倍速只改变墙钟节奏，不改变演算结果。
- **无头模式**：`runToEnd()` 连续步进至结束，可用于配平/测试；同 BD + 同 seed → 事件序列一致。
- **Max**：批量步进（可走 Web Worker），近即时跑完；失败时回退主线程演算。

### 2.2 行动流程（每个 tick 内）

```
每个 tick (100ms):
         │
         ▼
  ┌─────────────────────────┐
  │ 恢复所有单位的 HP 和耐力   │
  │ 所有武器 remainingTime    │
  │ 递减 100ms               │
  └──────────┬──────────────┘
             │
             ▼
  ┌─────────────────────────┐
  │ 遍历所有武器              │
  │ remainingTime ≤ 0 ?      │
  └──────────┬──────────────┘
             │
    ┌────────┴────────┐
    │ 否              │ 是
    ▼                 ▼
  ┌──────────┐   ┌─────────────────────────┐
  │ 跳过      │   │ 检查当前耐力              │
  └──────────┘   └──────────┬──────────────┘
                            │
                   ┌────────┴────────┐
                   │ 足够            │ 不足
                   ▼                 ▼
             ┌──────────┐   ┌──────────────────┐
             │ 立即行动  │   │ remainingTime = 0  │
             │ 扣除耐力  │   │ 下个 tick 再试      │
             └─────┬────┘   └──────────────────┘
                   ▼
  ┌─────────────────────────────┐
  │ 执行动作:                    │
  │ 1. 按 targetFaction 选目标   │
  │ 2. 按 targetType/targetOrder │
  │    选具体目标                 │
  │ 3. dmg = weaponDamage       │
  │ 4. 目标 HP -= dmg            │
  │    （正=伤害, 负=恢复）       │
  └──────────────┬──────────────┘
                 ▼
  ┌─────────────────────────────┐
  │ 重置倒计时:                  │
  │ remainingTime = actionTime   │
  └─────────────────────────────┘
```

### 2.3 耐力恢复机制

耐力在战斗中**持续每秒恢复**。

```
耐力恢复公式:
  当前耐力 = min(当前耐力 + 总耐力恢复速度 × 时间增量, 耐力上限)
```

### 2.4 生命恢复机制

生命在战斗中**持续每秒恢复**（仅当总生命恢复 > 0 时生效）。

```
生命恢复公式:
  当前生命 = min(当前生命 + 总生命恢复速度 × 时间增量, 总生命值)
```

**并行触发机制：**
- 同一 tick 内多把武器按顺序独立触发。
- 耐力不足的武器搁置到下个 tick（100ms 后）重试。
- 死亡单位的武器不再触发。

## 三、针对系统

决定武器如何选择攻击目标。优先级为：
**条件 Targeting > 优先目标位 > 针对顺序**。

### 3.1 针对目标（targetFaction）

决定动作的对付对象：

| 值 | 说明 |
|----|------|
| 友方 | 只在己方单位中选目标 |
| 敌人 | 只在敌方单位中选目标（默认） |
| 所有 | 同时搜索双方，对方优先 |

> **v7 变更**：`targetFaction` 可通过词条的 `targeting_modifier` 覆写（如「治疗引导」将针对目标改为友方）。

### 3.2 位置 Targeting（兜底）

当条件 Targeting 不存在或失效时，回退到位置 Targeting：

| 属性 | 说明 | 可选值 |
|------|------|--------|
| 优先目标位（priorityTarget） | 优先攻击对方第几位（1-based） | 1 / 2 / 3 / null |
| 针对顺序（targetOrder） | 兜底搜索方向 | 从上往下 / 从下往上 |

> @deprecated `targetType`（近战/远程）仅作 UI 展示标签，运行时忽略。标签从 targetOrder + priorityTarget 自动推导。

### 3.3 条件 Targeting（targetCondition）（v6 新增）

不按空间位置，而按**单位状态属性**选择目标。存在时优先级高于位置 Targeting。

```typescript
interface TargetCondition {
  sortBy?: 'hp_asc' | 'hp_desc' | 'stamina_asc' | 'random';  // 排序方式
  filterBy?: 'has_debuff' | 'most_buffs' | 'hp_below_50pct';  // 过滤条件
}
```

| 字段 | 值 | 说明 |
|------|-----|------|
| sortBy | hp_asc | 优先攻击 HP 最低的敌人 |
| sortBy | hp_desc | 优先攻击 HP 最高的敌人 |
| sortBy | stamina_asc | 优先攻击耐力最低的敌人 |
| sortBy | random | 随机选择目标 |
| filterBy | has_debuff | 只攻击有负面状态的目标（**预留**：战斗尚未维护 `_activeDebuffs`） |
| filterBy | most_buffs | 只攻击 Buff 最多的目标（**预留**：战斗尚未维护 `_activeBuffs`） |
| filterBy | hp_below_50pct | 只攻击 HP 低于 50% 的目标（已实现） |

> filterBy 过滤后候选池为空时，保留原始候选池（继续 sortBy 或兜底）。

### 3.4 Targeting 词条覆写（targeting_modifier）（v7 扩展）

`targeting_modifier` 分类的词条可覆写挂载实体的 **全部 5 个 targeting 字段**（v6 仅支持 sortBy/filterBy）。

#### 3.4.1 TargetingModifier 接口（v7）

```typescript
interface TargetingModifier {
  targetFaction?: TargetFaction | null;   // 覆写针对目标
  targetOrder?: string | null;            // 覆写针对顺序
  priorityTarget?: number | null;         // 覆写优先目标位
  sortBy?: TargetSortBy;                  // 覆写条件排序
  filterBy?: TargetFilterBy;              // 覆写条件过滤
}
```

- 每个字段的默认值为 **"不修改"**（= undefined，不参与覆写）
- 字段值为 `null` 时表示**清除该字段**（设为无值）
- 只有明确设置了值的字段才参与覆写

#### 3.4.2 主开关

词条表单中有一个整体主开关「覆写模式」：
- **"不修改"** → `targetingModifier` 不保存（undefined），所有子字段隐藏
- **"修改"** → 显示 5 个子字段，各有独立的「不修改」选项

#### 3.4.3 生效范围（Per-Entity）

- 词条的 targeting_modifier **只影响其直属实体**的武器
- 不影响同父实体的兄弟实体武器
- 不影响父实体的武器
- 递归子实体时，子实体可叠加自己的 targeting_modifier 词条

#### 3.4.4 覆写合并顺序

当一个实体挂载多个 targeting_modifier 词条时，按**实体 children 数组从前到后**依次合并：

```
实体短剑: targetFaction="敌人", priorityTarget=1, sortBy="hp_asc"
  ├── 词条A「狂乱」: {sortBy:"random"}          ← children[0]，先应用
  └── 词条B「弱点感知」（预留示例）: {filterBy:"has_debuff"} ← children[1]，后应用

合并过程：
  初始:  targetFaction="敌人", priorityTarget=1, sortBy="hp_asc", filterBy=undefined
  ↓ 词条A: sortBy="random" （覆写 sortBy）
  中间:  targetFaction="敌人", priorityTarget=1, sortBy="random", filterBy=undefined
  ↓ 词条B: filterBy="has_debuff"（追加 filterBy；预留：当前战斗无 debuff 数据，过滤实际不生效）
  最终:  targetFaction="敌人", priorityTarget=1, sortBy="random", filterBy="has_debuff"

→ selectTarget（设计意图）: 随机攻击有负面状态的敌人
→ 当前实现: 因无 debuff 状态，过滤池为空则回退原池，效果接近仅「狂乱」
```

合并规则：
- 只有词条中**明确设置的字段**（值 ≠ undefined）才参与覆写
- 未设置的字段不覆写，保留上一轮的值
- 后遍历的词条字段覆盖先遍历的（最后的值胜出）

### 3.5 目标选择完整流程

```
1. 按 targetFaction 筛选候选池
2. 过滤存活单位（currentHp > 0）
3. ┌─ targetCondition 存在？ ──────────────────────┐
   │  a. filterBy 过滤（池空则保留原池）             │
   │  b. sortBy 排序                                │  ← 条件优先！
   │  c. 返回 pool[0]                               │
   └────────────────────────────────────────────────┘
4. priorityTarget 检查（位置兜底）
   ├─ 有效位 + 存活 → 攻击该位置
   └─ 越界/死亡 → 进入步骤 5
5. targetOrder 搜索（最终兜底）
   ├─ 从上往下 → 返回 alive[0]
   └─ 从下往上 → 返回 alive[alive.length - 1]
6. 全部死亡 → 跳过该动作
```

### 3.6 判定示例（v7 新增）

#### 例1：纯位置 Targeting（传统行为）

```
武器: targetFaction="敌人", targetOrder="从上往下", priorityTarget=1
敌方: [哥布林A(20/20), 哥布林B(15/15)]
→ priorityTarget=1 → 打A（第1位）
→ 若A已死 → targetOrder兜底 → 打B（从上往下=第一个存活）
```

#### 例2：条件优先，位置字段被忽略

```
武器: targetFaction="敌人", targetCondition={sortBy:"hp_asc"}, priorityTarget=2
敌方: [A(20/20), B(10/30), C(25/25)]
→ targetCondition存在 → sortBy=hp_asc → 池=[B(10), A(20), C(25)] → 打B
→ priorityTarget=2 完全被忽略
```

#### 例3：filterBy + sortBy 组合

```
武器: targetFaction="敌人", targetCondition={sortBy:"hp_asc", filterBy:"hp_below_50pct"}
敌方: [A(20/20,满), B(10/30,<50%), C(5/25,<50%)]
→ filterBy → 池=[B(10), C(5)]
→ sortBy=hp_asc → 池=[C(5), B(10)] → 打C
```

#### 例4：filterBy 过滤后池空 → 保留原池

```
武器: targetFaction="敌人", targetCondition={filterBy:"hp_below_50pct"}
敌方: [A(20/20,满), B(30/30,满)]
→ filterBy → 池空 → 保留[A, B]
→ 无sortBy → pool[0]=A
```

#### 例5：词条覆写后（词条 > 实体定义）

```
实体短剑: targetFaction="敌人", targetOrder="从上往下"
词条「狂乱」: targetingModifier={sortBy:"random"}
→ 最终 targetCondition={sortBy:"random"}（词条覆写）
→ selectTarget: 随机打一个敌人
```

### 3.7 类型默认约定

| 标签 | 针对顺序 | 优先目标位 | 说明 |
|------|----------|------------|------|
| 近战（默认） | 从上往下 | 1 | 固定打前排第一位 |
| 远程 | 从下往上 | null | 从后排往前搜索 |

> 标签仅从 targetOrder + priorityTarget 推导，不影响运行时逻辑。

### 3.8 多可触发实体的独立目标选择

每个可触发实体**独立选目标**，条件 Targeting 也各自独立评估。

```
冒险者拥有：
  ├── 处刑之刃（targetCondition: { sortBy: 'hp_asc' }）→ 攻击 HP 最低的敌人
  └── 短剑（priorityTarget: 1, targetOrder: 从上往下）→ 攻击敌方第 1 位

每次独立触发，各自选目标！
```

## 四、伤害计算

### 4.1 伤害公式

```
dmg = weaponDamage
```

- 正 = 伤害（扣减目标 HP）。
- 负 = 恢复（增加目标 HP），**不可超过目标 HP 上限**。
- 零 = 无效果。
- **无最小值限制**，伤害可以为 0 或负值。
- **无护甲减伤**，直接扣减。
- **HP 上限保护**：恢复类动作（负伤害）受 HP 上限约束，`HP = min(HP, maxHP)`。

### 4.2 针对目标与伤害的交互

| targetFaction | 正伤害 | 负伤害 |
|---------------|--------|--------|
| 敌人 | 攻击敌方 | 恢复敌方 |
| 友方 | 攻击友方 | 恢复友方 |
| 所有 | 双方各扣 | 双方各恢复 |

### 4.3 计算示例

```
短剑（伤害 5, 针对目标=敌人）攻击敌方前排
  → dmg = 5, 敌方 HP -5

治疗杖（伤害 -10, 针对目标=友方, 针对顺序=从上往下）恢复己方第一位
  → dmg = -10, 己方 HP +10

震荡波（伤害 3, 针对目标=所有）同时攻击双方
  → 敌方每位各扣 3 HP, 己方每位各扣 3 HP
```

### 4.4 命中效果（On-Hit Effects）（v5.2 新增）

#### 概述

命中效果是武器造成正伤害后自动触发的额外效果，在伤害结算后独立执行。

#### 三类实体模型

一次武器命中涉及三种不同角色的实体：

| 角色 | 说明 | 示例 |
|------|------|------|
| 启动端实体 (starter) | 攻击者侧的 HP/耐力池所在 | life_steal 回复 starter 的 HP |
| 被触发动作实体 (actionOwner) | 实际拥有该武器的实体 | 未来 self_enhance 作用于该实体 |
| 被影响实体 (target) | 被命中方 | stamina_drain 削减 target 的耐力 |

#### 效果来源与传播规则

命中效果通过**词条（affix）**的 `onHitEffects` 字段定义。效果在战斗快照构建阶段注册到 `entityOnHitEffects` Map（`Map<instanceId, OnHitEffect[]>`），运行时通过 `map.get(weapon.ownerInstanceId)` 查表获取。

| affix 挂载位置 | 影响范围 |
|---------------|---------|
| starter 实体直属 | 传播到该 starter 自身（若 isActive）+ 所有子孙 isActive 实体 |
| 非 starter 的 isActive 实体直属 | 仅该实体的主动动作 |
| isActive=false 实体直属 | 不生效 |

#### 执行流程

1. 快照构建：`collectEntityOnHitEffects` 遍历实体树，每个 isActive 实体提取直属 affix 效果，注册到 Map
2. starter 传播：`calculateCombatSnapshots` 将 starter 直属效果追加到 Map 中所有子孙实体的 entry
3. 运行时：武器命中后，组装 `OnHitContext`（starter / actionOwnerId / target），通过 `entityOnHitEffects.get(weapon.ownerInstanceId)` 查表获取效果并逐个执行

#### 规则

- 仅正伤害（damage > 0）触发
- HP 回复受上限保护，耐力不低于 0
- 同类型效果叠加（独立结算，各产生日志标签）
- 效果在伤害结算之后，不影响当次伤害值

#### 当前效果

| type | 效果 | 参数 | 作用于 |
|------|------|------|-------|
| life_steal | 启动端实体回复HP | percent + amount | ctx.starter |
| stamina_drain | 被影响实体减少耐力 | percent + amount | ctx.target |

#### 参数计算

```typescript
effectAmount = Math.round(damage × (effect.params.percent ?? 0) / 100) + (effect.params.amount ?? 0)
```

- `percent` 模式：效果量 = 伤害 × 百分比（适合高伤武器）
- `amount` 模式：效果量 = 固定值（适合高频低伤武器）
- 混合模式：两者叠加取总和

## 五、死亡与复活

### 5.1 死亡
- HP ≤ 0 → 实体死亡。
- 死亡实体的武器不再触发，倒计时停止。
- 死亡实体的子孙实体退出战斗。

### 5.2 复活
- HP 恢复到 > 0 → 实体复活。
- 重新加入战斗，武器重新开始计时。

### 5.3 胜负条件
- **胜利**：敌方所有第一层实体 HP ≤ 0。
- **失败**：玩家方所有第一层实体 HP ≤ 0。
- **双方同灭**：玩家胜利。
- **120 秒上限到达**：玩家胜利。
- 详见「六、超时惩罚」。

## 六、超时惩罚

### 6.1 机制

战斗进行到 **60 秒** 后，进入软狂暴阶段。每秒对**双方所有第一层实体**造成一次递增伤害。

### 6.2 伤害公式

```
overtimeSeconds = floor((simTime - 60000) / 1000)   // 第1秒=1, 第2秒=2, ...
penaltyDamage   = overtimeSeconds × 10              // 10, 20, 30, ...
```

| 时间 | 伤害 | 累计 |
|------|------|------|
| 61s  | 10   | 10   |
| 62s  | 20   | 30   |
| 63s  | 30   | 60   |
| 64s  | 40   | 100  |
| 70s  | 100  | 550  |
| 120s | 600  | 18300 |

### 6.3 胜负判定

- 敌方全灭 → 玩家胜利
- 双方同时全灭 → 玩家胜利
- 120 秒上限到达 → 玩家胜利
- 仅玩家方全灭而敌方仍有存活 → 玩家失败

### 6.4 设计意图

- 防止纯恢复型 BD 导致战斗无法结束
- 递增伤害给双方施加越来越大的压力，强制分出胜负
- 120 秒时若仍未结束，判定玩家胜利

## 九、敌方来源

敌方有两种来源，按优先级排列：

### 9.1 在线对战池（优先）

玩家进入战斗阶段时，BD 自动上传到对战池，同时从池中随机抽取其他玩家的 BD 作为对手。

- **匹配规则**：同回合（round），随机抽取 1 个
- **不计算战力、不统计战绩、不分楼层**：对战池是纯粹的 BD 交换市场
- **池空处理**：对战池无对手或网络异常时，自动获胜（视为胜利，正常发放奖励）

详见 `doc/在线对战池-待实现.md`。

### 9.2 自动获胜（池空兜底）

当对战池中无可用对手时，系统直接判定玩家自动获胜，正常发放金币和 growth 奖励，不进入战斗引擎。

> 注：`generateEnemyBD()` 硬编码模板已不再被 `runCombat()` 调用，仅保留供参考或后续测试使用。

## 十、平衡参考

### 10.1 战斗时长目标
| 轮次 | 目标时长 | 说明 |
|------|----------|------|
| 回合 2 | 15~30 秒 | 教学，玩家基础 BD 可通过 |
| 回合 4 | 25~50 秒 | 需要一定的词条搭配 |
| 回合 6 | 40~80 秒 | 需要较完整的 BD 体系 |

### 10.2 耐力平衡参考
- 高频武器（匕首、短剑）：低耐力消耗，适合持续输出。
- 低频武器（战锤、法杖）：高耐力消耗，需要耐力强化词条支撑。
- 超重惩罚：+50% 耐力消耗，明显痛感但不至于完全无法战斗。

### 10.3 针对类型平衡
- 近战：稳定打前排，需要足够伤害快速击破肉盾。
- 远程：可绕过前排打后排，先消灭高输出低 HP 的远程敌人可降低承伤。
