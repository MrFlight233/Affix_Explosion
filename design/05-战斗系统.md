## 概述

战斗系统采用**基于时间线的全自动**战斗。核心机制：
- **耐力系统**：控制可触发动作的触发频率
- **负重系统**：超重惩罚耐力消耗
- **针对系统**：目标选择（位置 / 条件 Targeting）+ 针对目标（友方/敌人/所有）
- **无护甲**：伤害 = weaponDamage，直接扣减 HP

## 一、战斗前准备

### 1.0 正式战匹配与开战（客户端流程）

正式战斗与模拟战斗共用同一演算引擎与同一播放控件；差异仅在 BD 来源与战后结算。

**正式战顺序：**

1. 从对战池抽取**同回合**敌方 BD（空池则标记自动获胜）
2. 上传己方出场 BD 到对战池（在抽取之后，避免抽到自己刚上传的 BD）
3. **开战时自动存档**（含本场开战快照：双方 BD、combatSeed 等）；抽取后**不再二次抽池**
4. 立即开战，或空池直接进入自动胜**结束态**  
5. 战斗中可使用与模拟战相同的暂停 / 倍速（**1x · 2x · 4x · Max**）；**不得改变演算结果**  
6. 任意结果进入**战斗结束态**（写入本场战斗记录并自动存档），点「继续」再推进  

**网络异常：** 匹配/上传失败时提示网络异常，**留在探险回合**，可再次点击「开始战斗」重试；不进入战斗回合。

**模拟战：** 双方 BD 均为自建；播放控件与正式战共用模块。

### 1.1 第一层级检查
- 战斗开始时，扫描出场面板，识别所有**第一层级**的实体。
- 先执行**0.0s 开战预处理相位**：所有被动加成在全单位上生效一次（含 HP 为 0 的单位），配合上限同步机制将 0 血单位拉起到目标 HP；此相位**不开火、不回复**，并将「来源 → 目标 → 效果」写入战斗日志；此阶段不进行常规死亡判定，相位结束时对仍为 0 血的单位记击杀。
- 预处理完成后进入常规 tick（自 0.1s 起）；HP > 0 的单位存活。
- 拥有 `starter` 词条的实体加入行动时间线。
- 无 `starter` 的实体放在第一层 = 木桩（有 HP 可被攻击，不触发动作）。
- **验证规则**：拥有 `starter` 词条的实体不允许放在非第一层级。

### 1.2 第一层槽位检查
- 第一层槽位数 = `floor((round + 1) / 2)`。
- 所有第一层实体的 `slotCost` 之和 ≤ 第一层槽位数。
- 超出时无法开始战斗。

### 1.3 构建战斗数据
对每个 starter 实体，汇总自身属性 + 所有子孙实体的属性：

| 汇总属性 | 计算方式 |
|----------|----------|
| 总生命值 | 基础 HP + 被动 maxHp 修饰 + 命中持续底盘；**上限提升时，当前生命值同步增长相等量** |
| 总生命恢复 | 基础 + 被动 hpRegen + 持续底盘 |
| 总耐力上限 | 基础 + 被动 maxStamina + 持续底盘；**上限提升时，当前耐力同步增长相等量** |
| 总耐力恢复 | 基础 + 被动 staminaRegen + 持续底盘 |
| 当前负重 | Σ(所有子孙实体重量) |
| 负重上限 | 基础 maxLoad + 被动 maxLoad + 持续底盘 |
| 可触发动作列表 | 自身 isActive + 收集所有子孙中 isActive=true 的实体 |

**启动端自身动作**：当启动端实体自身的 `isActive=true` 时，其自身作为一个可触发动作加入时间线：
- 武器名称 = 启动端实体名称
- 使用启动端自身的 damage / actionTime / staminaCost / targetFaction / targetCount / targetCondition（统一 sortBy + filterBy[]）
- 耐力消耗从启动端自身的耐力池扣除，受到超重惩罚（+50%）
- 受到子孙实体的伤害加成（与其他子武器相同）
- 在武器列表中排在第一位（子实体武器之前）

### 1.4 被动伤害加成

**定义**：实体的 `damageBonus` 字段是一个独立于 `isActive` 的被动伤害加成——一个全局被动值，会加至父启动端的所有可触发武器上。

**聚合规则**：
- 递归遍历启动端的所有子孙实体（包括启动端自身）
- 每个 `hasPassiveBonuses` 的实体 → `passiveDamageBonus += entity.damageBonus`（`isActive=false` 时）
- 每个 `hasPassiveBonuses` 的词条 → `passiveDamageBonus += affix.damageBonus`
- 该实体自身的子孙继续递归，其 `passiveDamageBonus` 也向上累加

**符号匹配（v5.1 新增）**：
- 正的伤害加成（+N）只影响基础伤害为正的武器——增伤配件不会弱化治疗效果
- 负的伤害加成（-N）只影响基础伤害为负的武器（治疗武器）——诅咒配件不会削弱输出
- 零伤害加成无效果

**生效范围**：
- 影响父启动端的**所有子孙实体**中 `isActive=true` 的实体的武器伤害
- 包括启动端自身的主动动作（如果启动端 `isActive=true`）
- 不影响其他启动端——每个启动端的 `passiveDamageBonus` 独立计算

**示例**：
```
冒险者（starter, isActive=true, damage=10）装备:
  ├── 力量戒指（damageBonus=+5）  ← 被动伤害加成，独立于 isActive
  └── 吸血匕首（isActive=true, damage=-8）   ← 治疗武器

计算结果:
  - 冒险者自身武器: damage=10（正伤害），收到 +5 加成 → 最终 15
  - 吸血匕首: damage=-8（负伤害/治疗），+5 加成不匹配符号 → 保持 -8
  - 如果力量戒指 damageBonus=-3: 冒险者武器不受影响（正不匹配负），吸血匕首变为 -11（增强治疗）
```

### 1.5 超重判定
```
有效负重上限 = 基础 maxLoad + 被动 maxLoad 修饰 + 命中持续底盘
if 当前负重 > 有效负重上限:
    超重状态 = true
    该实体下所有可触发动作 staminaCost × 1.5
else:
    超重状态 = false
```

被动加成：子树配置聚合到**第一层实体**（含木桩），按目标每 tick 全量重算；来源死亡硬收。不受 targeting_modifier。详见 [02-名词解释](./02-名词解释.md) 被动相关条目。

**UI**：BD 卡面/悬浮窗用 `previewBdRuntimes` 显示被动后数值；开战即重算并写入 `combat*Units`，卡面与悬浮窗读 runtime（含耐回/生命恢复/负重/战斗修饰），`battlePatch` 同步刷新。快照只存基础值，禁止写回被动结果。

## 二、战斗进行

### 2.1 时间线模型

战斗使用**固定时间步长**（100ms / tick）。逻辑上每 100ms 推进一帧，全局时间统一前进：

```
时间线（全局统一，每 100ms 一帧）:
  Tick 0   (0ms):    所有武器 init（remainingTime = actionTime）
  Tick 1   (100ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  Tick 2   (200ms):  恢复 HP/耐力, remainingTime -= 100ms, 触发到期武器
  ...
  Tick 20  (2000ms): 短剑 cd=2000ms 到期，触发！
```

- 同一个 tick 内可能有**多把武器同时触发**，按玩家→敌人、武器列表顺序依次处理。
- 先触发的武器击杀目标后，后续武器通过目标存活检查自动跳过已死亡单位。

#### 演算与播放分离（实现层）

客户端将战斗拆为两层（不影响上表逻辑规则）：

| 层 | 职责 |
|----|------|
| **BattleSimulator（演算）** | 同步 `step()` / `runToEnd()`，无墙钟等待；事件写入缓冲 |
| **Playback（播放）** | 按倍速（1x / 2x / 4x / Max）消费步进或回放；暂停只影响播放，不改变演算结果 |

约定：

- **逻辑 tick 仍为 100ms**；倍速只改变墙钟节奏，不改变演算结果。
- **无头模式**：`runToEnd()` 连续步进至结束，可用于配平/测试；同 BD + 同 seed → 事件序列一致。
- **Max**：批量步进（可走 Web Worker），近即时跑完；失败时回退主线程演算。

### 2.2 行动流程（每个 tick 内）

```
每个 tick (100ms):
         │
         ▼
  ┌─────────────────────────┐
  │ 恢复所有单位的 HP 和耐力   │
  │ 所有武器 remainingTime    │
  │ 递减 100ms               │
  └──────────┬──────────────┘
             │
             ▼
  ┌─────────────────────────┐
  │ 遍历所有武器              │
  │ remainingTime ≤ 0 ?      │
  └──────────┬──────────────┘
             │
    ┌────────┴────────┐
    │ 否              │ 是
    ▼                 ▼
  ┌──────────┐   ┌─────────────────────────┐
  │ 跳过      │   │ 检查当前耐力              │
  └──────────┘   └──────────┬──────────────┘
                            │
                   ┌────────┴────────┐
                   │ 足够            │ 不足
                   ▼                 ▼
             ┌──────────┐   ┌──────────────────┐
             │ 立即行动  │   │ remainingTime = 0  │
             │ 扣除耐力  │   │ 下个 tick 再试      │
             └─────┬────┘   └──────────────────┘
                   ▼
  ┌─────────────────────────────┐
  │ 执行动作:                    │
  │ 1. 合并池选目标（阵营OR）     │
  │ 2. 属性AND → 统一sortBy →取N │
  │ 3. 按序对每个目标结算         │
  │    dmg = weaponDamage         │
  │    （正=伤害, 负=恢复）       │
  └──────────────┬──────────────┘
                 ▼
  ┌─────────────────────────────┐
  │ 重置倒计时:                  │
  │ remainingTime = actionTime   │
  └─────────────────────────────┘
```

### 2.3 耐力恢复机制

耐力在战斗中**持续每秒恢复**。

```
耐力恢复公式:
  当前耐力 = min(当前耐力 + 总耐力恢复速度 × 时间增量, 耐力上限)
```

### 2.4 生命恢复机制

生命在战斗中**持续每秒恢复**（仅当总生命恢复 > 0 时生效）。

```
生命恢复公式:
  当前生命 = min(当前生命 + 总生命恢复速度 × 时间增量, 总生命值)
```

**并行触发机制：**
- 同一 tick 内多把武器按顺序独立触发。
- 耐力不足的武器搁置到下个 tick（100ms 后）重试。
- 死亡单位的武器不再触发。

## 三、针对系统（v8+）

**合并池取 N**：阵营 OR → 存活 → 属性 AND → **统一 sortBy** → 取前 N / 全部 → 按序结算。  
**缺省排序 = random**。阵营**只**在 `filterBy` 中配置；**无阵营标签 = 空池**（仍扣耐力）。已删除 `targetFaction` / `targetType` / `targetOrder` / `priorityTarget`（旧档映射）。

### 3.1 过滤（filterBy[]）

| 来源 | 说明 |
|------|------|
| 阵营标签 | `友方`/`敌人`/`根实体` **OR**；全无 → 空池空放 |
| 属性标签 | `not_root`/`is_starter`/`is_stake`/`hp_below_50pct`/… **AND**；池空则保留过滤前池。`has_debuff`/`most_buffs` 为**预留**（Admin 条件行不暴露；战斗未维护对应状态，配置无效） |
| 旧 targetFaction | 仅当 filter 无阵营时并入（`所有`→友方+敌人） |

### 3.2 统一排序与目标数量

同前：`sortBy` + `targetCount`（默认 1 / `all`）。

### 3.3 targeting_modifier

可覆写：`sortBy` / `filterBy[]` / `targetCount`。遗留 `targetFaction` 读档并入过滤。  
`filterBy`：有值=覆写，省略=不修改；Admin 不再写入 `null` 清除（历史 `null` 仅兼容读）。

### 3.4 流程

```
武器触发（先扣耐力）
  → 阵营 OR（无则空池 → 重置 CD）
  → 存活 → 属性 AND → sortBy → 取 N → 按序结算
```

### 3.5 示例

| 配置 | 结果 |
|------|------|
| filter 含敌人 + 从上往下 + N=2 | 敌方前 2 |
| filter 无阵营 | 空放耗耐 |
| filter 含根实体 | 发动者 |
| 旧档仅 targetFaction=敌人 | 运行时等价 filter 含敌人 |

## 四、伤害计算

### 4.1 伤害公式

```
dmg = weaponDamage
```

- 正 = 伤害（扣减目标 HP）。
- 负 = 恢复（增加目标 HP），**不可超过目标 HP 上限**。
- 零 = 无效果。
- **无最小值限制**，伤害可以为 0 或负值。
- **无护甲减伤**，直接扣减。
- **HP 上限保护**：恢复类动作（负伤害）受 HP 上限约束，`HP = min(HP, maxHP)`。

### 4.2 针对目标与伤害的交互

| targetFaction / filter 阵营 | 正伤害 | 负伤害 |
|---------------------------|--------|--------|
| 敌人 | 攻击敌方 | 恢复敌方 |
| 友方 | 攻击友方 | 恢复友方 |
| 根实体 | 攻击发动者 | 恢复发动者 |
| 无阵营 | 空放（已扣耐力） | 同左 |
| 多阵营 filter | 按合并池命中单位结算 | 同上 |

### 4.3 计算示例

```
短剑（伤害 5, 针对目标=敌人）攻击敌方前排
  → dmg = 5, 敌方 HP -5

治疗杖（伤害 -10, 针对目标=友方, 针对顺序=从上往下）恢复己方第一位
  → dmg = -10, 己方 HP +10

震荡波（伤害 3, 针对目标=所有）同时攻击双方
  → 敌方每位各扣 3 HP, 己方每位各扣 3 HP
```

### 4.4 命中效果（On-Hit Effects）

命中效果是主动动作选中目标后，按武器最终 `onHitEffects` 列表**有序结算**的数值变化。不再要求「先有正伤害」。分为 **即时** 与 **持续**（术语见 [CONTEXT.md](../CONTEXT.md)）。

#### 三类结算对象（`applyTo`，多选不互斥）

| 值 | 中文 | 说明 |
|----|------|------|
| `target` | 被命中 | 默认；未配置时等同于此 |
| `actionOwner` | 被触发 | 拥有本武器的实体（当前运行时与 starter 共用战斗单位池） |
| `starter` | 启动端 | 攻击方该槽启动端 |

多选时同一 `value` 对各角色**各结算一遍**。

#### 挂载范围（注册进哪些武器）

| 宿主 | 范围 |
|------|------|
| 启动端 | 该 starter 全部 isActive 武器 |
| 非 starter 且 isActive | 仅该武器 |
| 非主动且非 starter | 不生效 |

同宿主上：实体自身 `onHitEffects` 与直属词条列表**语义等价**，按序拼接。

#### 数值结构（冻结共识）

```typescript
{
  displayName: string;
  kind: 'instant' | 'duration';
  durationMs?: number;       // duration 必填
  tickIntervalMs?: number;   // 有则 Tick 壳，无则底盘修饰（互斥）
  buffKey?: string;          // 遗留：与名称对齐；轨道以 displayName 为准
  stat: string;              // 见白名单：即时=当前池/本轮CD；持续底盘=上限/回复/武器耗时耐耗/重压
  op: 'gain' | 'loss' | 'set'; // 持续仅 gain|loss
  params: { amount?: number; percent?: number };
  applyTo?: Array<'starter'|'actionOwner'|'target'>;
}
```

```
value = floor(cap × percent / 100) + amount
```

`cap` 为该属性对应上限（回复借 HP/耐力上限；武器类相对开战快照）。持续施加/覆盖时算死。**不再**用本次伤害量作通用 percent 分母。

白名单、同名全覆盖、Tick 施加/覆盖均立即跳、重压与超重、死亡清持续等见上文与 [02-名词解释](./02-名词解释.md)「命中效果」。

展示与日志优先用 `displayName`（配置面文案称「名称」）；配置面一行一效果（多角色 `/` 合并）；战斗日志按结算对象可拆行；持续含时长。

**配置面**（卡/悬浮/Admin）：
- 即时：`{displayName} {角色} {属性} {+/-/→} {量}`
- Tick 壳：`{displayName} {角色} 每{间隔}s {属性} {+/-} {量} 总{时长}s`（例：`毒 被命中 每1.0s 血量 - 5 总2.0s`）
- 底盘持续：`{displayName} {角色} {属性} {+/-} {量} 总{时长}s`
量例 `10` / `20%` / `5 + 10%`；多选 `applyTo` 时角色用 `/` 写在同一行（如 `被命中/启动端`），不拆行。Admin 持续名称标签为「名称（同名互抢）」，必填且本模板内不可重名。

**战斗日志子行**：`{displayName} {单位名} {属性} {+/-/→} {值}  (前 -> 后)`（即时）；持续为 `{名} {单位} 施加|覆盖 {属性} ±值 (Xs)`。

主动动作 UI 固定三块：消耗（耐耗+耗时/倒计时）→ 目标（摘要）→ 效果（上式多行）。Admin 二级标题为主动消耗/主动目标/主动效果；卡面无副标题，用 `主动目标:` 与引导行 `主动效果` 区分。

被动 `damageBonus` 已移除；旧主动 `damage` 读档迁移为 hp 增减效果。

## 五、死亡与复活

### 5.1 死亡
- HP ≤ 0 → 实体死亡（无最低 HP 保护；被动/持续效果可将 HP 从 0 拉起，例如预初始化阶段）。
- 死亡实体的武器不再触发，倒计时停止。
- 死亡实体的子孙实体退出战斗。

### 5.2 复活
- HP 恢复到 > 0 → 实体复活。
- 重新加入战斗，武器重新开始计时。
- 战斗开始后的每 tick，死亡单位（HP ≤ 0）不再作为被动源和目标。

### 5.3 胜负条件
- **胜利**：敌方所有第一层实体 HP ≤ 0。
- **失败**：玩家方所有第一层实体 HP ≤ 0。
- **双方同灭**：玩家胜利。
- **120 秒上限到达**：玩家胜利。
- 详见「六、超时惩罚」。

## 六、超时惩罚

### 6.1 机制

战斗进行到 **60 秒** 后，进入软狂暴阶段。每秒对**双方所有第一层实体**造成一次递增伤害。

### 6.2 伤害公式

```
overtimeSeconds = floor((simTime - 60000) / 1000)   // 第1秒=1, 第2秒=2, ...
penaltyDamage   = overtimeSeconds × 10              // 10, 20, 30, ...
```

| 时间 | 伤害 | 累计 |
|------|------|------|
| 61s  | 10   | 10   |
| 62s  | 20   | 30   |
| 63s  | 30   | 60   |
| 64s  | 40   | 100  |
| 70s  | 100  | 550  |
| 120s | 600  | 18300 |

### 6.3 胜负判定

- 敌方全灭 → 玩家胜利
- 双方同时全灭 → 玩家胜利
- 120 秒上限到达 → 玩家胜利
- 仅玩家方全灭而敌方仍有存活 → 玩家失败

### 6.4 设计意图

- 防止纯恢复型 BD 导致战斗无法结束
- 递增伤害给双方施加越来越大的压力，强制分出胜负
- 120 秒时若仍未结束，判定玩家胜利

## 七、战斗结算

### 7.1 奖励

| 结果 | 金币 | 物品掉落 |
|------|------|----------|
| 获胜（含空池自动胜） | `floor((round + 1) / 2) × 5` | 无 |
| 失败 | `0` | 无 |

探险回合金币与战斗奖励分离，见 [02-名词解释](./02-名词解释.md)。

### 7.2 结束态与推进

- 胜/负/空池自动胜均进入**战斗结束态**，写入本场战斗记录并自动存档。
- 玩家点击「继续」后进入下一探险，或（回合 10）进入结算页。
- **失败不中断本局**，仅本场战斗奖励为 0。

### 7.3 结算页与战斗回顾字段

本局结算与历史归档中，每场战斗记录建议包含：

| 字段 | 说明 |
|------|------|
| round | 战斗回合号 |
| result | win / loss / auto_win 等 |
| rewardGold | 本场战斗金币 |
| playerBd / enemyBd | 开战快照；空池时敌方可为 null |
| combatSeed | 开战种子（崩溃重播用） |
| durationMs / endedBy | 逻辑时长、结束原因 |
| log | **全文**战斗日志（空池可空或一条胜利记录） |

进行中存档与历史归档的分工见 [01-游戏概述 · 存档与历史归档](./01-游戏概述.md#存档与历史归档)。

## 八、战斗日志示例

日志子行来自命中效果结算（含单位名与前后值）。**不**根据伤害占比自动附加「重击 / 大回复」类装饰标签。抬头不写总伤害/总 HP。

```
[1.0s] 人类 对 哥布林 使用 拳头
	伤害 哥布林 血量 - 10  (HP: 50 -> 40)
	吸血 人类 血量 + 2 (HP: 80 -> 82)
[1.0s] 哥布林 击杀!
```

抬头：`{actor} 对 {target} 使用 {weapon}`。空效果时可无子行或一行「（无效果）」。

## 九、敌方来源

### 9.1 在线对战池（优先）

玩家进入战斗阶段时，**先**从对战池抽取同回合敌方 BD，**再**上传己方 BD（避免抽到自己）。

- **匹配规则**：同回合（round），随机抽取 1 个
- **不计算战力、不统计战绩**：对战池是纯粹的 BD 交换市场
- **网络异常**：不视为自动获胜；留在探险，可重试

### 9.2 自动获胜（池空兜底）

当对战池中无可用对手时，系统直接判定玩家自动获胜，发放满额战斗金币，不进入战斗引擎演算；进入结束态面板（可点继续）。结算/历史回顾中占一条；日志可空或一条「玩家胜利」。

> 注：硬编码敌人模板不再作为正式战默认来源。

## 十、平衡参考

### 10.1 战斗时长目标
| 轮次 | 目标时长 | 说明 |
|------|----------|------|
| 回合 2 | 15~30 秒 | 教学，玩家基础 BD 可通过 |
| 回合 4 | 25~50 秒 | 需要一定的词条搭配 |
| 回合 6 | 40~80 秒 | 需要较完整的 BD 体系 |

### 10.2 耐力平衡参考
- 高频武器（匕首、短剑）：低耐力消耗，适合持续输出。
- 低频武器（战锤、法杖）：高耐力消耗，需要耐力强化词条支撑。
- 超重惩罚：+50% 耐力消耗，明显痛感但不至于完全无法战斗。

### 10.3 目标配置平衡
- 站位序（从上往下 / 站位k）：稳定点前排或固定格，需足够伤害破盾。
- 站位中间 + N>1：中心扩散 AoE，适合清场但不保证打到后排核心。
- 百分比排序 / 残血过滤：处刑与治疗向更强，可用耗时与伤害数值制衡。
- 缺省随机 + 多阵营合并：不稳定，适合趣味词条而非主力输出。
