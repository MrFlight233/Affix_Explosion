## 一、游戏阶段

### 回合（Round）

游戏进度的基本单位。回合从 1 开始递增。

- 奇数回合（1、3、5…）= **探险阶段**
- 偶数回合（2、4、6…）= **战斗阶段**
- **取消「层」概念**，只保留回合；**无成长/growth**，强度随回合推进。
- 默认 **最大回合数 = 10**（可配置调高）；回合 10 为最后一场战斗。
- **Round=1 探险**：发放探险金；从事件池抽 3 个事件选 1；可访问固定商人、配置 BD。
- **Round=2 战斗**：自动战斗。结束后进入**战斗结束态**，点「继续」后进入下一探险（非最终回合）或结算（最终回合）。

### 通关

打完默认最后一战（回合 10）并进入结算即通关，**与中间战斗胜负场次无关**。

### 战斗结束态

一场战斗（含空池自动胜）已出结果后的停留界面。玩家需点击「继续」才会进入下一探险或结算。结束态可查看结果与日志；不强制局内复盘。

### 结算页

通关后的本局总结。版式为三分区（上统计 / 左场次列表 / 右选中场详情）。只回顾**战斗回合**；详情含双方 BD、结果、战斗日志等（空池/失败均记入）。

### 阶段流转

```
探险 → 战斗 → 结束态 → [继续] → 探险 → … → 回合10结束态 → [继续] → 结算(通关)
```

### 金币

- 初始：**40** 金（配置可改）
- 进入探险回合时发放：`floor((round + 1) / 2) × 10`（与开局金币叠加；回合 1 亦发放）
- 战斗获胜：`floor((round + 1) / 2) × 5`
- 战斗失败：**0**
- 空池自动胜：按获胜发放

## 二、实体模型（统一模型）

### 实体（Entity）

游戏中的基本战斗单位。所有实体拥有相同的属性结构（hp、maxStamina、staminaRegen、maxLoad）。

- 不再区分"启动端"、"装备"、"主动装备"、"被动装备"等硬编码类别。
- "武器"、"防具"、"饰品"等仅为描述性词条标签。
- 实体放在第一层还是子孙槽位决定了其战斗行为。

### starter 词条

- 拥有 `starter` 词条的实体 = 第一层战斗单位。
- 自身 `isActive=true` 时会独立在时间线上触发动作。
- 子孙中 `isActive=true` 的实体也会被父实体触发。
- **不能放入其他实体的实体槽位中**。

### 无 starter 的实体

- 放在第一层 → 木桩（有 HP 可被攻击，无动作触发）。
- 放入其他实体槽位 → 占用槽位，有 `isActive` 时由父实体触发（消耗父实体耐力）。

### isActive（主动动作）

- 布尔属性。界面一级分区与开关文案为「主动动作」；有（true）= 可在时间线上触发动作；无（false）= 不进入主动触发。
- 每个可触发实体独立计时、独立触发、互不阻塞。
- Admin 展开后二级分区：主动消耗 → 主动目标 → 主动效果。详见 [doc/2026-08-05-主动动作分区对齐.md](../doc/2026-08-05-主动动作分区对齐.md)。

### 属性显示规则

- **HP**：始终显示。
- **耐力上限 / 耐力恢复 / HP恢复 / 负重上限**：仅在拥有 `starter` 词条时显示。

## 三、实体层级

### 第一层级（Top Level）

出场面板中直接放置的实体，处于嵌套结构的最外层。

- 第一层总槽位 = `floor((round + 1) / 2)`。
- 只有拥有 `starter` 词条的实体才能参与战斗行动时间线。

### 子孙实体（Descendant Entity）

放入某个实体槽位中的子实体，以及子实体的子实体（递归）。

- 继承父实体的触发机制。
- 重量计入父实体的当前负重。

### 实体槽位（Entity Slot）

- 部分实体拥有实体槽位，可以容纳子实体。
- 实体槽位数量由实体的 `entitySlots` 属性决定。

### 占有槽位（Slot Cost）

实体或词条占用父级槽位的大小。

- **统一算法**：已用槽位 = 下属各项 `slotCost` 之和；`slotCost === 0` 不计入、不减少空槽格。
- 第一层总占用 ≤ 第一层槽位数（`floor((round+1)/2)`）。
- 实体子槽：直属子实体 `slotCost` 之和 ≤ 父实体 `entitySlots`。
- 动态词条槽：挂载动态词条 `slotCost` 之和 ≤ 宿主 `dynamicAffixSlots`。

## 四、物品系统

### 物品（Item）

游戏中最基本的可收集单位。分为**实体**和**词条**两种类型。  
所有物品共有属性：价值、占有槽位、重量。  
正式局中物品来自**事件**与**商人**，战斗不掉落物品。

### 词条（Affix）

需要附加到实体上才能生效的能力/属性。词条可配置与实体同构的被动加成（`passiveEffects` + 被动目标），挂载到第一层实体子树上时由战斗引擎聚合。命中效果见 `onHitEffects`（与实体同结构）。详见 [04-词条介绍](./04-词条介绍.md)。

### 被动加成

实体与词条可配置「无耐耗、无耗时」的被动：完整目标配置 + 影响数据列表（HP/耐力/负重上限与回复）。子树配置向上聚合到**第一层实体**（含木桩），视作该实体产生；存活期间每 tick 按目标维持，死亡硬收。与主动不同：主动须启动端才能触发。

每条 `PassiveEffect` 可带可选的 `condition?: SubtreeCondition`（子树条件），仅在启动端全局子树中指定词条数量满足 `min`/`max` 时该条效果生效。不达标直接过滤不注入运行时。条件检查在快照构建阶段执行一次。

与命中持续底盘分工：存在式长驻走被动；有时限状态走命中持续。详见 [doc/2026-08-04-被动加成目标与存在生效.md](../doc/2026-08-04-被动加成目标与存在生效.md)。

### 被动加成总开关（hasPassiveBonuses）

- **有** → 编辑目标与效果列表；引擎采集
- **无** → 跳过并清零
- Admin「被动加成」主开关；旧五列自动迁入 `passiveEffects`

### 固定词条（Fixed Affix）

实体自带的词条，不可拆卸、不可升级、不可修改。定义实体的核心特性。

### 动态词条（Dynamic Affix）

可自由装卸的词条，玩家可在实体间任意移动。

### 物品池（Item Pool）

决定玩家当前可能遇到哪些物品的集合。运行时 `itemPool` 为可售/可抽商品的 `defId` 列表，**按当前持有实时重建**：遍历仓库与 BD 得到 `owned`（实体另计入模板 `fixedAffixes`），凡 `poolPrerequisite` 均在 `owned` 中的实体/词条进入池；无前置者始终在池。出售导致不再持有前置时，依赖商品立刻出池。生成商店货架或事件商人随机抽样前都会重建。

### 出场（Deploy）

玩家选择上场的实体与词条组合（BD）。

## 五、商人系统

### 固定商人（Fixed Merchant）

玩家在探险阶段可随时访问的商人。

- 出售范围：物品池中，价值 ≤ `round × 10` 的物品。

### 随机商人（Random Merchant）

通过事件池出现的商人。

| 商人类型 | 规则 |
|----------|------|
| 好物商人 | 随机 6 个物品，价值区间 `[上限, 上限+3]` |
| 实体好物商人 | 同上，只出售实体物品 |
| 词条好物商人 | 同上，只出售词条物品 |
| 折扣商人 | 随机 6 个物品，价格 = 原价 × 50% |
| 抽奖 | 随机 6 个物品，免费选 1 个获得 |

---

## 六、经济系统

### 金币（Gold）

游戏中的货币。初始 **40** 金币（配置可改）。

- 出售价格 = `floor(总价值 / 2)`。
- 购买价格 = 物品总价值。
- 探险发金与战斗发金相互独立，见「一、游戏阶段 · 金币」。

### 价值（Value）

- **本体价值（初始价值）**：模板字段本身。实体为 `value`，词条为 `abs(costValue)`。用于商人货架准入（`round × 10`）、事件随机价值区间、管理端编辑该字段。
- **总价值（动态价值）**：实例按价值树合计——本体 + 固定词条 + 子树（动态词条与子实体）递归；无实例时按模板默认交付结构（对齐 `createItem`：固定词条、预装动态词条、`defaultChildren`）合计。用于购买价、出售半价、商店标价、卡片/悬停「价值」、全物品池列表栏。
- 购买价格 = 总价值（事件可覆盖为半价/免费）。
- 出售价格 = `floor(总价值 / 2)`。
- 商人价值上限筛货架：按**本体**，`round × 10`。

## 七、战斗 — 耐力系统

### 耐力（Stamina）

启动端用于触发动作的能量资源。

- 每个启动端拥有独立的耐力池。
- 耐力在战斗时间线中持续恢复。

### 耐力上限（Max Stamina）

实体的耐力最大值。

### 耐力消耗（Stamina Cost）

触发可触发动作所消耗的耐力值。

- 如果当前耐力不足，该次行动被**搁置**。
- 搁置期间耐力持续恢复，一旦达到所需值，**立即**触发。

### 耐力恢复速度（Stamina Regen）

耐力每秒自然恢复的数值。单位：点/秒。

- 含子实体装备的耐力加成。

### 耐力不足与并行等待

```
多个可触发实体的行动时机到达 → 各自检查耐力
  ├── 耐力 ≥ 消耗 → 立即行动
  └── 耐力 < 消耗 → 各自搁置
         └── 谁的耐力先恢复到 ≥ 消耗 → 谁先触发（互不阻塞）
```

## 八、战斗 — 负重系统

### 重量（Weight）

每个实体都拥有重量属性。数据单位：**克**（g）。

- **模拟对战 UI 展示**：绝对值 &lt; 1000 显示为 `{n}g`，≥ 1000 显示为千克（如 `80kg`、`1.5kg`）；负重上限与负重加成同规则。存储与战斗计算仍用克。

### 负重上限（Max Load）

启动端能承载的子孙实体总重量的最大值。

- **有效负重上限** = 自身 `maxLoad` + 被动 maxLoad 修饰 + 命中持续底盘（BD 静态预览含被动推演）
- 超出有效负重上限时，该实体下**所有可触发动作的 staminaCost × 1.5**。

### 负重加成（Load Bonus）

被动效果 `stat=maxLoad` 的俗称；由第一层实体按目标维持。

### 当前负重（Current Load）

启动端下所有子孙实体的重量之和。

### 超重惩罚

```
超重状态 = 当前负重 > 有效负重上限（maxLoad + ΣloadBonus）
超重时：实际耐力消耗 = 基础耐力消耗 × 1.5
```

## 九、战斗 — 针对系统（v8+）

主动动作选目标：**阵营合并池 → 属性过滤 → 统一排序 → 取前 N（或全部）**，再按序结算。

### 阵营过滤（仅 filterBy）

- **`filterBy: string[]`**：多选过滤。
  - **阵营标签**（`友方`/`敌人`/`自己`）→ **OR** 并入合并池。
  - **属性标签**（`not_self`/`is_starter`/`is_stake`/`hp_below_50pct`/`has_debuff`/`most_buffs`/`has_affix:*`…）→ **AND**。
- **无任何阵营标签 → 候选池为空**：动作仍触发、扣耐力、重置 CD，不结算目标。
- 已删除配置项 **`targetFaction`（针对目标）**；旧档在无阵营过滤时把遗留 `targetFaction` 并入 `filterBy`（`所有`→友方+敌人）。
- 属性过滤后池空 → **保留过滤前池**（与旧行为一致）。

例：过滤含 `自己` + 伤害=-10 → 自疗；`友方` + `not_self` + `hp_pct_asc` → 奶队友不奶自己。

### 拥有词条过滤（has_affix:*）

`has_affix:ID1,ID2`（如 `has_affix:fighter,spell_casting`）：匹配单位子树中是否包含任一指定词条 ID。与 `has_route_*` 不同，不限于路线词条，可匹配任意词条。Admin 面板提供「拥有词条」多选控件，列出所有词条 ID 供策划勾选。判定基于 `CombatUnitRuntime.affixIds`（启动端子树：affix 实例 + 各实体 `fixedAffixes`），在快照构建阶段收集；与 `SubtreeCondition` 计数**同源**。

> 旧格式 `has_route_*` 不再用于新种子产出，但引擎仍向前兼容读取。

### 统一排序（sortBy）

**一个 `sortBy`** 覆盖原「针对顺序 / 条件排序 / 优先目标位」。**缺省 = `random`**（未配置且无旧顺序字段时）。

| sortBy | 说明 |
|--------|------|
| 从上往下 / 从下往上 | 本方第一层站位序 |
| 站位1…站位5 | 该站位置顶，其余从上往下接龙 |
| 站位中间 | 按到队形中心距离升序（中心优先，同距先上后下） |
| hp_asc / hp_desc | 当前 HP 绝对值 |
| hp_pct_asc / hp_pct_desc | HP 百分比 |
| stamina_asc / stamina_desc | 当前耐力绝对值 |
| stamina_pct_asc / stamina_pct_desc | 耐力百分比 |
| random | 打乱后再取 N（**缺省**） |

站位下标 = 单位在**本侧第一层部署数组**中的位置（0-based ↔ 站位1）。合并池跨阵营时：先比各单位本侧下标；同站位号时固定 **敌方优先于友方**。

旧档兼容：`priorityTarget=k` → `站位k`（优先）；否则 `targetOrder` / 旧 `sortBy` → 对应确定性排序；二者皆空的新默认才是 `random`。已废弃独立配置项 `targetOrder` / `priorityTarget`；`targetType`（近战/远程）忽略。

### 目标数量（targetCount）

`number | 'all'`，默认 **1**。排序后取前 N 或全部；耐力按触发扣一次；每个目标一条日志 / on-hit。

### targeting_modifier

词条可覆写：`sortBy` / `filterBy[]` / `targetCount`（遗留 `targetFaction` 读档时并入过滤）。  
主开关「覆写模式」；Per-Entity；children 从前到后浅合并，后写覆盖先写。

### 目标选择流程

1. 阵营 OR 合并池（仅 filter 阵营标签；无则空池）。
2. 存活过滤。
3. 属性 AND 过滤（池空则回退上一步池）。
4. 统一 `sortBy`（缺省 random）。
5. 取前 N 或全部 → 按序结算；无目标则空放耗耐。

## 十、战斗 — 通用

### 伤害（Damage）

由命中效果管道中对目标的 `hp`+`loss`（及回复等）结算，不再使用独立的 `weapon.damage` 字段作为主伤害源。旧配置的 `damage` 会迁移为一条命中效果。

### 命中效果（On-Hit Effect）

主动命中后按武器最终 `onHitEffects` 有序结算。分为 **即时效果** 与 **持续效果**（见根目录 [CONTEXT.md](../CONTEXT.md)）。

- **挂载范围**：启动端 → 全部主动；武器 → 仅自身。
- **结算对象**：`applyTo` 多选（启动端 / 被触发 / 被命中），缺省被命中。
- **白名单**：改底盘必须持续（有寿命）；当前池与本轮 CD 只能即时。持续禁止 `set`；一条持续要么底盘修饰要么 Tick 壳（毒）。
- **量**：`floor(cap × percent/100) + amount`，`cap` 为该属性对应上限（回复借 HP/耐力上限；武器耗时/耐耗/倒计时相对开战快照）。持续挂上时算死。不再用本次伤害量作通用 percent 分母。
- **持续同一性**：`buffKey`；同键刷新满时长且数值取 max；Tick 壳刷新不重跳。不同键并行，同属性代数相加。死亡清空该单位全部持续。
- **重压**：与装备负重分离；超重 = 装备负重 + 重压 > 负重上限。
- **配置面 / 日志**：即时与持续文案区分。Tick 壳：`{名} {角色} 每{间隔}s {属性} {+/-} {量} 总{时长}s`；底盘持续：`… {属性} {+/-} {量} 总{时长}s`。多选作用对象合并规则同前。详见 [doc/2026-08-04-命中效果即时与持续.md](../doc/2026-08-04-命中效果即时与持续.md)。
- **子树条件触发（condition）**：`OnHitEffect` 和 `PassiveEffect` 均可选带 `condition?: SubtreeCondition`。条件在快照构建阶段（开战前）评估一次，不达标的效果直接过滤不注入运行时。始终从启动端全局子树统计指定词条 ID 的数量，对比 `min`/`max` 阈值。`matchIds` 中任一匹配即计入。多级阶梯奖励 = 多条 effect 各有不同阈值。详见下方「子树条件触发」。

主动动作卡面/悬浮/Admin 统一「消耗 → 目标 → 效果」三块；Admin 用二级标题主动消耗/主动目标/主动效果，卡面用行标签区分。详见 [05-战斗系统](./05-战斗系统.md) §4.4、§八 与 [doc/2026-08-03-主动动作三块展示.md](../doc/2026-08-03-主动动作三块展示.md)、[doc/2026-08-05-主动动作分区对齐.md](../doc/2026-08-05-主动动作分区对齐.md)。

### 耐力恢复（Stamina Regen）

实体在战斗中每秒恢复的耐力值。

- 总耐力恢复 = 自身 staminaRegen + 自身耐力恢复加成 + 子孙实体耐力恢复加成(staminaRegenerationBonus)之和

### 生命恢复（HP Regen）

实体在战斗中每秒恢复的生命值。默认为 0。

- 总生命恢复 = 基础 hpRegen + 被动 hpRegen 修饰 + 命中持续底盘

### 耐力上限加成（Stamina Bonus）

被动效果 `stat=maxStamina` 的俗称。

- 总耐力上限 = 基础 maxStamina + 被动 maxStamina + 持续底盘

### 生命加成（HP Bonus）

被动效果 `stat=maxHp` 的俗称。

### 耗时（Action Time）

实体执行一次行动的时间间隔，单位：毫秒。

### 生命值（HP）

实体在战斗中的存活指标。HP ≤ 0 时失去战斗能力（死亡）。

### 第一层槽位（First Layer Slots）

第一层槽位数量 = `floor((round + 1) / 2)`。

- 所有第一层实体占用其 `slotCost` 数量的槽位。
- 总占用 ≤ 第一层槽位数量。

### 死亡与复活

- HP ≤ 0 → 死亡：子孙实体退出战斗，动作停止触发。
- HP 恢复到 > 0 → 复活：重新加入战斗，武器重新开始计时。
- 一方所有第一层实体 HP ≤ 0 → 该方战败（玩家失败时本局仍可推进，见 [01](./01-游戏概述.md)）。

---

## 十一、在线对战池

### 对战池（Battle Pool）

玩家异步匹配对战的数据池。玩家进入战斗阶段时，BD 自动上传到对战池，同时从池中随机抽取**同回合**其他玩家的 BD 作为对手。

- 不计战力、不统计战绩。
- 空池 → 自动获胜（结束态 + 满额战斗奖励）。
- 网络异常 → 留在探险，可重试开始战斗，不进入战斗回合。

### BD（Build / 构筑）

玩家出场面板的完整配置，包含所有第一层实体及其嵌套的子孙实体和词条。序列化为 `DeploySlot[]` JSON 格式存储和传输。

---

## 十二、事件系统

### 事件池（Event Pool）

探险阶段从中随机抽取 3 个事件，玩家选 1 个触发。  
现阶段以满足回合推进为准；种类与权重的详细设计另做。

读档时，当前回合的事件选项须与存档**完全一致**。

---

## 十三、存档与历史

### 进行中存档

每用户最多 **1** 份，用于「继续游戏」。通关后删除；新游戏覆盖进行中存档，不清除历史。

自动存节点、读档与开战重播规则见 [01-游戏概述 · 存档与历史归档](./01-游戏概述.md#存档与历史归档)。

### 历史归档（爬塔回顾）

多局记录，**暂不设上限**。本局**首场战斗结束后**即可入库（进行中），之后每场增量更新；通关标为已通关。每局含各战斗场次的双方 BD、结果、**全文战斗日志**等。新游戏不清除历史。

## 公式汇总

| 名称 | 公式 |
|------|------|
| 开局金币 | `40`（可配置） |
| 探险阶段金币 | `floor((round + 1) / 2) × 10`（进入该探险时发放） |
| 战斗获胜金币 | `floor((round + 1) / 2) × 5` |
| 战斗失败金币 | `0` |
| 出售价格 | `floor(总价值 / 2)` |
| 购买价格 | 总价值（事件可覆盖） |
| 固定商人价值上限 | 按本体 `value`/`abs(costValue)` ≤ `round × 10` |
| 第一层槽位数 | `floor((round + 1) / 2)` |
| 默认最大回合 | `10`（可配置） |
| 实际伤害 | 由武器 `onHitEffects` 管道结算（无独立 weapon.damage） |
| 命中效果量 | `floor(hitMagnitude × percent/100) + amount` |
| 当前负重 | `Σ 实体下所有子孙实体的重量` |
| 有效负重上限 | `基础 maxLoad + 被动 maxLoad + 持续底盘` |
| 超重惩罚 | `若 当前负重 > 有效负重上限 → 耐力消耗 × 1.5` |
| 总生命值 | `基础 HP + 被动 maxHp + 持续底盘` |
| 总耐力上限 | `基础 maxStamina + 被动 maxStamina + 持续底盘` |
| 总耐力恢复 | `基础 staminaRegen + 被动 staminaRegen + 持续底盘` |
| 总生命恢复 | `基础 hpRegen + 被动 hpRegen + 持续底盘` |
| 耐力恢复 | `每秒按有效耐力恢复回复` |

## 十四、子树条件触发（SubtreeCondition）

`SubtreeCondition` 是 `OnHitEffect` 和 `PassiveEffect` 上的可选字段，用于控制效果只有在启动端全局子树中拥有指定数量的指定词条时才生效。

### 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `matchIds` | `string[]` | 要检测的词条 ID 列表（任一匹配即计入） |
| `min` | `number`（可选） | 至少多少个才生效 |
| `max` | `number`（可选） | 不超过多少个才生效 |

### 语义

- 条件始终从**启动端全局子树**统计指定词条的**出现次数**
- 计数包含：递归所有 `type==='affix'` 实例 + 子树内每个实体的 `fixedAffixes` 数组项（同实体固定与动态同 ID **分别计入**）
- 范围等价于 `DeploySlot.entity` + `DeploySlot.children`（及各自嵌套 `children`）
- `min` 和 `max` 可同时指定（如 `min:2, max:5` = 2~5 个词条时生效）
- 多级阶梯奖励 = 多条 effect，各有不同 `min`/`max`
- 选目标过滤 `has_affix:*` 与条件**同源**（运行时 `affixIds` 同样计入 fixedAffixes）

### 关键规则

- 条件在快照构建阶段评估一次（开战前），不达标的效果直接过滤；**战中不重判**
- BD 编辑阶段每次预览会重算（HP / 未生效浅色实时）
- 无 condition 或条件不达标的效果不会注入运行时；效果所属物品仍可使用，仅该条效果不触发
- 条件不影响 `filterBy` 的其它标签；`has_affix:*` 与条件计数规则一致
- 不可重复词条（`repeatable:false`）：目标已拥有该 ID（含 fixed）时不可再挂

### Admin 编辑

Admin 面板中条件编辑器为**极简句子式 UI**：
- 效果行内展开「触发条件」折叠区
- 开关：启用/关闭（关闭则效果始终生效）
- 拥有词条：popover 多选器选择词条 ID
- 方向：≥ / ≤
- 数量：正整数
- 旧格式条件（scope/mode/sumStat 等）不回填，打开默认关
