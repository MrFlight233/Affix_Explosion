## 一、游戏阶段

### 回合（Round）

游戏进度的基本单位。回合从 1 开始递增。

- 奇数回合（1、3、5…）= **探险阶段**
- 偶数回合（2、4、6…）= **战斗阶段**
- **取消「层」概念**，只保留回合；**无成长/growth**，强度随回合推进。
- 默认 **最大回合数 = 10**（可配置调高）；回合 10 为最后一场战斗。
- **Round=1 探险**：发放探险金；从事件池抽 3 个事件选 1；可访问固定商人、配置 BD。
- **Round=2 战斗**：自动战斗。结束后进入**战斗结束态**，点「继续」后进入下一探险（非最终回合）或结算（最终回合）。

### 通关

打完默认最后一战（回合 10）并进入结算即通关，**与中间战斗胜负场次无关**。

### 战斗结束态

一场战斗（含空池自动胜）已出结果后的停留界面。玩家需点击「继续」才会进入下一探险或结算。结束态可查看结果与日志；不强制局内复盘。

### 结算页

通关后的本局总结。版式为三分区（上统计 / 左场次列表 / 右选中场详情）。只回顾**战斗回合**；详情含双方 BD、结果、战斗日志等（空池/失败均记入）。

### 阶段流转

```
探险 → 战斗 → 结束态 → [继续] → 探险 → … → 回合10结束态 → [继续] → 结算(通关)
```

### 金币

- 初始：**90** 金（配置可改）
- 进入探险回合时发放：`floor((round + 1) / 2) × 10`（与开局金币叠加；回合 1 亦发放）
- 战斗获胜：`floor((round + 1) / 2) × 5`
- 战斗失败：**0**
- 空池自动胜：按获胜发放

## 二、实体模型（统一模型）

### 实体（Entity）

游戏中的基本战斗单位。所有实体拥有相同的属性结构（hp、maxStamina、staminaRegen、maxLoad）。

- 不再区分"启动端"、"装备"、"主动装备"、"被动装备"等硬编码类别。
- "武器"、"防具"、"饰品"等仅为描述性词条标签。
- 实体放在第一层还是子孙槽位决定了其战斗行为。

### starter 词条

- 拥有 `starter` 词条的实体 = 第一层战斗单位。
- 自身 `isActive=true` 时会独立在时间线上触发动作。
- 子孙中 `isActive=true` 的实体也会被父实体触发。
- **不能放入其他实体的实体槽位中**。

### 无 starter 的实体

- 放在第一层 → 木桩（有 HP 可被攻击，无动作触发）。
- 放入其他实体槽位 → 占用槽位，有 `isActive` 时由父实体触发（消耗父实体耐力）。

### isActive（可触发动作）

- 布尔属性。有（true）= 可在时间线上触发动作；无（false）= 被动属性生效。
- 每个可触发实体独立计时、独立触发、互不阻塞。

### 属性显示规则

- **HP**：始终显示。
- **耐力上限 / 耐力恢复 / HP恢复 / 负重上限**：仅在拥有 `starter` 词条时显示。

## 三、实体层级

### 第一层级（Top Level）

出场面板中直接放置的实体，处于嵌套结构的最外层。

- 第一层总槽位 = `floor((round + 1) / 2)`。
- 只有拥有 `starter` 词条的实体才能参与战斗行动时间线。

### 子孙实体（Descendant Entity）

放入某个实体槽位中的子实体，以及子实体的子实体（递归）。

- 继承父实体的触发机制。
- 重量计入父实体的当前负重。

### 实体槽位（Entity Slot）

- 部分实体拥有实体槽位，可以容纳子实体。
- 实体槽位数量由实体的 `entitySlots` 属性决定。

### 占有槽位（Slot Cost）

实体或词条占用父级槽位的大小。

- **统一算法**：已用槽位 = 下属各项 `slotCost` 之和；`slotCost === 0` 不计入、不减少空槽格。
- 第一层总占用 ≤ 第一层槽位数（`floor((round+1)/2)`）。
- 实体子槽：直属子实体 `slotCost` 之和 ≤ 父实体 `entitySlots`。
- 动态词条槽：挂载动态词条 `slotCost` 之和 ≤ 宿主 `dynamicAffixSlots`。

## 四、物品系统

### 物品（Item）

游戏中最基本的可收集单位。分为**实体**和**词条**两种类型。  
所有物品共有属性：价值、占有槽位、重量。  
正式局中物品来自**事件**与**商人**，战斗不掉落物品。

### 词条（Affix）

需要附加到实体上才能生效的能力/属性。词条拥有与实体相同的结构化被动加成字段（damageBonus、hpBonus、staminaBonus、hpRegenerationBonus、staminaRegenerationBonus、loadBonus），挂载到启动端子树上时由战斗引擎统一聚合。详见 [04-词条介绍](./04-词条介绍.md)。

### 被动加成总开关（hasPassiveBonuses）

实体与词条共用的布尔属性，控制是否拥有被动加成效果。

- **有**（true）→ 引擎在战斗快照构建时读取该对象的被动加成字段（含负重加成）
- **无**（false）→ 引擎跳过该对象的所有被动字段读取
- 用于快速筛选：无被动加成的词条（如 targeting_modifier、命中效果类）设此开关为 false
- 在 Admin 表单中通过「被动加成」（有/无）主开关控制，选择「无」时被动字段隐藏且保存时全部清零
- 旧实体迁移：任一既有被动字段非 0 → 自动回填为有

### 固定词条（Fixed Affix）

实体自带的词条，不可拆卸、不可升级、不可修改。定义实体的核心特性。

### 动态词条（Dynamic Affix）

可自由装卸的词条，玩家可在实体间任意移动。

### 物品池（Item Pool）

决定玩家可能遇到哪些物品的池子。

### 出场（Deploy）

玩家选择上场的实体与词条组合（BD）。

## 五、商人系统

### 固定商人（Fixed Merchant）

玩家在探险阶段可随时访问的商人。

- 出售范围：物品池中，价值 ≤ `round × 10` 的物品。

### 随机商人（Random Merchant）

通过事件池出现的商人。

| 商人类型 | 规则 |
|----------|------|
| 好物商人 | 随机 6 个物品，价值区间 `[上限, 上限+3]` |
| 实体好物商人 | 同上，只出售实体物品 |
| 词条好物商人 | 同上，只出售词条物品 |
| 折扣商人 | 随机 6 个物品，价格 = 原价 × 50% |
| 抽奖 | 随机 6 个物品，免费选 1 个获得 |

## 六、经济系统

### 金币（Gold）

游戏中的货币。初始 **90** 金币（配置可改）。

- 出售价格 = `floor(动态价值 / 2)`。
- 购买价格 = 物品动态价值。
- 探险发金与战斗发金相互独立，见「一、游戏阶段 · 金币」。

### 价值（Value）

- **初始价值**：物品的基础价值。
- **动态价值**：受词条/事件影响后的当前价值。
- 商人价值上限：`round × 10`。

---

## 七、战斗 — 耐力系统

### 耐力（Stamina）

启动端用于触发动作的能量资源。

- 每个启动端拥有独立的耐力池。
- 耐力在战斗时间线中持续恢复。

### 耐力上限（Max Stamina）

实体的耐力最大值。

### 耐力消耗（Stamina Cost）

触发可触发动作所消耗的耐力值。

- 如果当前耐力不足，该次行动被**搁置**。
- 搁置期间耐力持续恢复，一旦达到所需值，**立即**触发。

### 耐力恢复速度（Stamina Regen）

耐力每秒自然恢复的数值。单位：点/秒。

- 含子实体装备的耐力加成。

### 耐力不足与并行等待

```
多个可触发实体的行动时机到达 → 各自检查耐力
  ├── 耐力 ≥ 消耗 → 立即行动
  └── 耐力 < 消耗 → 各自搁置
         └── 谁的耐力先恢复到 ≥ 消耗 → 谁先触发（互不阻塞）
```

---

## 八、战斗 — 负重系统

### 重量（Weight）

每个实体都拥有重量属性。数据单位：**克**（g）。

- **模拟对战 UI 展示**：绝对值 &lt; 1000 显示为 `{n}g`，≥ 1000 显示为千克（如 `80kg`、`1.5kg`）；负重上限与负重加成同规则。存储与战斗计算仍用克。

### 负重上限（Max Load）

启动端能承载的子孙实体总重量的最大值。

- **有效负重上限** = 自身 `maxLoad` + Σ(子树内实体/词条的 `loadBonus`)（含启动端自身；仅 `hasPassiveBonuses=true` 时计入）
- 超出有效负重上限时，该实体下**所有可触发动作的 staminaCost × 1.5**。

### 负重加成（Load Bonus）

被动加成：为最近启动端增加负重上限。与其它被动一样向上聚合到启动端。

### 当前负重（Current Load）

启动端下所有子孙实体的重量之和。

### 超重惩罚

```
超重状态 = 当前负重 > 有效负重上限（maxLoad + ΣloadBonus）
超重时：实际耐力消耗 = 基础耐力消耗 × 1.5
```

## 九、战斗 — 针对系统

### 针对目标（Target Faction）

可触发动作的对付对象：

- **友方**：效果作用于己方单位。
- **敌人**：效果作用于敌方单位。
- **所有**：效果同时作用于双方。

例：针对目标="友方"、伤害=-10 → 给己方恢复 10 HP。

> **v7 变更**：`targetFaction` 可通过词条的 `targeting_modifier` 覆写。

### 针对顺序（Target Order）

兜底搜索方向：**从上往下** / **从下往上**。条件 Targeting 失效时生效。

### 优先目标位（Priority Target）

优先攻击对方第几位（1-based）：**1 / 2 / 3 / null**。条件 Targeting 失效时生效。

### 条件 Targeting（Target Condition）（v6 新增）

不按空间位置、而按**单位状态属性**选择目标的机制。

| 排序方式 | 说明 |
|----------|------|
| hp_asc | 优先攻击 HP 最低的敌人 |
| hp_desc | 优先攻击 HP 最高的敌人 |
| stamina_asc | 优先攻击耐力最低的敌人 |
| random | 随机选择目标 |

| 过滤条件 | 说明 |
|----------|------|
| has_debuff | 只攻击有负面状态的目标（**预留**：战斗尚未维护 `_activeDebuffs`，配置后过滤不生效） |
| most_buffs | 只攻击 Buff 最多的目标（**预留**：战斗尚未维护 `_activeBuffs`，配置后过滤不生效） |
| hp_below_50pct | 只攻击 HP 低于 50% 的目标（已实现） |

> 条件 Targeting 存在时**优先级高于**优先目标位和针对顺序，后者降级为兜底。

### targeting_modifier（v7 扩展）

一种词条分类，用于**覆写挂载实体的全部 targeting 字段**（v6 仅支持 sortBy/filterBy）。

支持的覆写字段：`targetFaction`、`targetOrder`、`priorityTarget`、`sortBy`、`filterBy`。  
每个字段默认"不修改"，只有明确设置的值才参与覆写。

**生效范围**（Per-Entity）：词条只影响其直属实体的武器，不影响兄弟实体或父实体。  
**合并顺序**：多个 targeting_modifier 词条按 children 数组从前到后依次浅合并，后遍历的字段覆盖先遍历的。  
**主开关**：词条表单有"覆写模式"（不修改/修改）总开关控制是否启用覆写。

### 兜底策略（Fallback）

条件 Targeting 不匹配（如候选池空）时，回退到位置 Targeting（priorityTarget → targetOrder）。

### 目标选择流程

1. 按 `targetFaction` 筛选候选目标。
2. 过滤存活单位。
3. 若 `targetCondition` 存在 → 条件过滤 + 排序，返回结果。
4. 否则按 `priorityTarget` 检查位置。
5. 否则按 `targetOrder` 方向搜索兜底。

## 十、战斗 — 通用

### 伤害（Damage）

实体行动时对目标造成的基础伤害值。

- **dmg = weaponDamage**（无最小值限制）。
- 正 = 伤害，负 = 恢复 HP，零 = 无效果。

### 命中效果（On-Hit Effect）（v5.2 新增）

武器造成正伤害后自动触发的额外效果。效果由词条的 `onHitEffects` 字段定义。

一次命中涉及三类实体：

- **启动端实体 (starter)**：攻击者侧的 HP/耐力池。life_steal 回复其 HP。
- **被触发动作实体 (actionOwner)**：实际拥有该武器的实体。
- **被影响实体 (target)**：被命中方。stamina_drain 削减其耐力。

挂载在 starter 上时传播到子树所有 isActive 实体的动作，挂载在单个武器上时仅该实体的动作生效。

效果量计算公式：`Math.round(damage × percent/100) + amount`

### 耐力恢复（Stamina Regen）

实体在战斗中每秒恢复的耐力值。

- 总耐力恢复 = 自身 staminaRegen + 自身耐力恢复加成 + 子孙实体耐力恢复加成(staminaRegenerationBonus)之和

### 生命恢复（HP Regen）

实体在战斗中每秒恢复的生命值。默认为 0。

- 总生命恢复 = 自身 hpRegen + 自身生命恢复加成 + 子孙实体生命恢复加成(hpRegenerationBonus)之和

### 耐力上限加成（Stamina Bonus）

被动加成：为最外层启动端增加耐力上限。

- 总耐力上限 = 自身 maxStamina + 自身 staminaBonus + 子孙实体 staminaBonus 之和

### 生命加成（HP Bonus）

被动加成：为最外层启动端增加生命上限。

### 耗时（Action Time）

实体执行一次行动的时间间隔，单位：毫秒。

### 生命值（HP）

实体在战斗中的存活指标。HP ≤ 0 时失去战斗能力（死亡）。

### 第一层槽位（First Layer Slots）

第一层槽位数量 = `floor((round + 1) / 2)`。

- 所有第一层实体占用其 `slotCost` 数量的槽位。
- 总占用 ≤ 第一层槽位数量。

### 死亡与复活

- HP ≤ 0 → 死亡：子孙实体退出战斗，动作停止触发。
- HP 恢复到 > 0 → 复活：重新加入战斗，武器重新开始计时。
- 一方所有第一层实体 HP ≤ 0 → 该方战败（玩家失败时本局仍可推进，见 [01](./01-游戏概述.md)）。

## 十一、在线对战池

### 对战池（Battle Pool）

玩家异步匹配对战的数据池。玩家进入战斗阶段时，BD 自动上传到对战池，同时从池中随机抽取**同回合**其他玩家的 BD 作为对手。

- 不计战力、不统计战绩。
- 空池 → 自动获胜（结束态 + 满额战斗奖励）。
- 网络异常 → 留在探险，可重试开始战斗，不进入战斗回合。

### BD（Build / 构筑）

玩家出场面板的完整配置，包含所有第一层实体及其嵌套的子孙实体和词条。序列化为 `DeploySlot[]` JSON 格式存储和传输。

---

## 十二、事件系统

### 事件池（Event Pool）

探险阶段从中随机抽取 3 个事件，玩家选 1 个触发。  
现阶段以满足回合推进为准；种类与权重的详细设计另做。

读档时，当前回合的事件选项须与存档**完全一致**。

---

## 十三、存档与历史

### 进行中存档

每用户最多 **1** 份，用于「继续游戏」。通关后删除；新游戏覆盖进行中存档，不清除历史。

自动存节点、读档与开战重播规则见 [01-游戏概述 · 存档与历史归档](./01-游戏概述.md#存档与历史归档)。

### 历史归档（爬塔回顾）

多局记录，**暂不设上限**。本局**首场战斗结束后**即可入库（进行中），之后每场增量更新；通关标为已通关。每局含各战斗场次的双方 BD、结果、**全文战斗日志**等。新游戏不清除历史。

| 名称 | 公式 |
|------|------|
| 开局金币 | `90`（可配置） |
| 探险阶段金币 | `floor((round + 1) / 2) × 10`（进入该探险时发放） |
| 战斗获胜金币 | `floor((round + 1) / 2) × 5` |
| 战斗失败金币 | `0` |
| 出售价格 | `floor(动态价值 / 2)` |
| 固定商人价值上限 | `round × 10` |
| 第一层槽位数 | `floor((round + 1) / 2)` |
| 默认最大回合 | `10`（可配置） |
| 实际伤害 | `dmg = weaponDamage`（无最小值，负值=恢复） |
| 命中效果量 | `Math.round(damage × percent/100) + amount` |
| 当前负重 | `Σ 实体下所有子孙实体的重量` |
| 有效负重上限 | `自身 maxLoad + Σ(子树实体/词条 loadBonus)`（含自身，受 hasPassiveBonuses 约束） |
| 超重惩罚 | `若 当前负重 > 有效负重上限 → 耐力消耗 × 1.5` |
| 总生命值 | `自身 HP + Σ(子孙实体 hpBonus) + Σ(子孙词条 hpBonus)` |
| 总耐力上限 | `自身 maxStamina + Σ(子孙实体 staminaBonus) + Σ(子孙词条 staminaBonus)` |
| 总耐力恢复 | `自身 staminaRegen + Σ(子孙实体 staminaRegenerationBonus) + Σ(子孙词条 staminaRegenerationBonus)` |
| 总生命恢复 | `自身 hpRegen + Σ(子孙实体 hpRegenerationBonus) + Σ(子孙词条 hpRegenerationBonus)` |
| 总伤害加成 | `自身 damageBonus + Σ(子孙实体 damageBonus) + Σ(子孙词条 damageBonus)`，正→正伤害武器，负→治疗武器 |
| 耐力恢复 | `每秒恢复 (基础耐力恢复 + 实体/词条被动耐力恢复加成) 点` |
