## 好 vs 坏

| 好 | 坏 |
|----|----|
| `project/client/src/ui/sim-battle.ts` 委托 `pointerdown`，松手一次 `commitPointerDrag` | 「优化一下拖拽体验」 |
| 验收：`slotCost=2` 在剩余 1 槽时拖入失败 | 验收：「拖拽正常」 |
| 状态：`已被取代` + 相对链接到新方案 | 留两份互相矛盾的「现行方案」不标注 |
| 列 `design/02`、`03`、`04` 同步项 | 改槽位算法却只改代码、不提 design |
| 「明确不做：不引入 SortableJS」 | 范围无限，执行智能体自行发挥 |

## 选用提示

- 单点缺陷、根因可定位 → **A Bug**
- 交互/UI/局部算法、文件数少 → **B 功能·小重构**
- 跨 types/DB/engine/UI 的新管线或大改规则 → **C 大型机制**
